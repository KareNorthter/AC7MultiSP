## 当前交互

1. 降落后进入原生补给页，选择 SP1。左信息栏显示当前候选，右栏保留原有 SP2；若新候选与 SP2 不兼容，显示“待重选”。
2. 选择 SP2，也可选无兵装。左栏固定为已选 SP1，右栏显示当前候选。返回可重选 SP1。
3. 起飞页保留两栏，初始选中 **NO**。NO 返回 SP1 修改方案；返回键回到 SP2；导航到 YES 后按游戏原生决定键起飞。按住决定键不会连选或跳过步骤。
4. YES 只暂存方案；原生补给成功并恢复原任务机体后，才重建、补给和保存。NO、返回、悬停和进入起飞页都不修改任务中的兵装、弹药或配置。

F8 仍只是管理界面，打开时暂停补给输入，关闭后继续同一草稿。任务中的直接选择键在补给期间不生效。已打开草稿的配弹比例不会被中途保存 F8 设置改写。

## 原生接入与恢复

双栏的空间来自原生视频区及类型区，行距来自原生性能项。只复制文字和图片叶控件的模板，创建空 Canvas 容器，不复制带子控件或 Slots 的 UserWidget。保留原背景、光标和设备按键提示；旧单栏及视频完整保留在折叠源容器中，退出时恢复。Canvas 自动尺寸属性也保存和恢复，避免原性能组恢复后变成零尺寸。

起飞 YES 在真实按键边沿上记录请求，等待决定键释放后，在下一次游戏线程 tick 恢复原生页面输入，再调用当前绑定 `MiniGamePhase` 的 `OnFinishdSupplyMenuHandler()`。历史反射记录确认该函数无参数，结束事件只保留待提交事务；待 `OnSuccessSupplyPhaseHandler` 到达后才清理控件、保存方案并重建武器。按键已释放后再交还输入，不会把同一决定键重复交给原单 SP 处理器；返回后必须完成一次双 SP 确认事务，否则明确报错。

函数签名和资源结构不是完整实机时序验证。用户第二轮实玩确认光标曾完全消失，YES 后短暂黑屏并回到不刷新的 YES/NO 页；日志仍停在 `NATIVE_RESUPPLY_FINISH_ACCEPTED`。当前候选已改为行内非负坐标并在结束入口前恢复原生输入，真实菜单创建、动画退出、连续补给与检查点仍待用户复测，详见[精简对照依据](../evidence/ac8-resupply-comparison.json)。
