## 事务与武器状态

| 原生事件/阶段 | 候选行为 |
|---|---|
| `Mission:OnStartSupplyPhaseHandler` | 绑定任务、机体和返航前配置；暂停切换及 HUD 弹药读取 |
| `MiniGamePhase:OnStartSupplyMenuHandler` | 绑定打开菜单的阶段，接入真实 `MissionResupplyWidget` |
| `MiniGamePhase:OnFinishdSupplyMenuHandler` 前/后 | 观察真实 YES 引发的结束通知；严格匹配菜单开始阶段，分别验证阶段关卡和任务 World，后回调标记完成，仍等任务成功后提交 |
| `MiniGamePhase:OnCloseSupplyMenu` | 单独关闭不提交；若确认了真实返回输入，则明确取消草稿并保留返航前方案 |
| `Mission:OnSuccessSupplyPhaseHandler` | 标记成功，等待原任务玩家武器与输入恢复可用 |
| 成功后游戏线程更新 | 将原生单 SP 选择对齐 SP1，重建新组合并补给，最后保存机体配置 |

普通导弹继续由游戏武器初始化补给。双 SP 从各自新兵装的完整初始状态建立独立缓存，再应用既有配弹比例；更换组合时不沿用旧武器的消耗和装填队列。SP2 为空时只初始化 SP1，不向双 SP 核心传入无效索引。

补给期间如果机体暂时离开当前世界，待确认事务保留；成功返回时检查机体 ID 和原任务世界，不能套用到其他任务。退出到菜单或同一玩家机体触发检查点恢复时取消未完成事务。机体重生的其他检查点路径仍需实玩核对。

`resupply_setup` 重建当前核心会话，但保留此前的核心检查点快照。Lua 同时保留检查点对应的 SP1/SP2 配置；恢复旧检查点时恢复旧方案，不把返航后的新方案配上旧弹药快照。后续真正的任务阶段捕获仍可更新检查点。这只是源码设计与审阅结论，真实任务的保存时机尚未验证。

页面接入失败、阶段不匹配、补给成功但未收到双选确认、不同任务/机体返回、核心协议缺失都会明确报错并停用武器修改。不自动切回 F8，也不把旧方案补满冒充本次重选成功。
