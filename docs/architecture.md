## 数据与调度

原生双选草稿 → 确认事务 → 按机体保存方案 → 游戏线程武器核心 → HUD。渲染线程只读内存状态，不访问 UE 对象；F8 设置和选择请求交给游戏线程校验。

短命令/状态文件只用于需要的核心事务，带请求编号，状态完整写完后原子替换。任务中不周期写武器快照，空 UI 动作队列不写文件。所有 Lua 更新和延迟输入均在游戏线程，不重新引入异步回调并发。

菜单对象按世界缓存，全局发现每 500 ms 一次；反射激活事件直接传入页面，短周期只检查缓存可见性。非任务世界不扫描 PlayerPlane。STANDBY 在进入/重新开放控制时刷新，PART 每 250 ms 读已装部件，静态信息与弹药颜色只在变化时写。活动补给等待页面期间每 20 ms 发现，正常飞行不扫描补给页。每 15 秒 PERF_TICK 汇总 Lua 回调均值/峰值，不代表整帧开销。见[性能说明](performance-polish.md)。

## 武器与音效

InitializeWeaponSystem 会重建系统：保存普通导弹、机炮/干扰弹、两套 SP 计数、装填队列及捕获时间，再映射到新槽位，用游戏时间推进冷却，不能复用旧实例指针。

每次重建之前逐槽释放锁定音引用，检查归零后再初始化。切换走完整 PlayerPlane 按下/释放流程，使锁定组件重新绑定并应用部件修正，不能只 ToggleSpecial。逻辑切换完成后统一提交箭头、简称和选择音。

TLS 离开前使用共用收尾虚函数自然结束光束；玩家 TLS 为 AttachedInstantWeapon，不以 LaserWeapon 的 Tick 判断。动态槽池按实际数组与可读范围检查，不设 64 槽上限（ADMM 历史实例为 126）。

selection_wave.hpp 使用系统 XAudio2 2.9，SP2 WAV 增益为原生音效音量的 0.175 倍；游戏线程同步暂停与音量，解绑先销毁声源再释放样本。MSL/SP1 使用原生音效。普通导弹保留上一 SP 挂载，双模型未实现。

## 页面与提交

准备页一次确认 SP1、一次确认 SP2，随后交还真实原生动作进入 STANDBY；SP1 返回交还取消。光标预览与保存分离，原生 setter 被调用不等于确认；保存还要求真实决定、相同机体/世界和原页面交接。

双栏只复制叶控件，不复制 UserWidget/Slots 子树；运行时布局支持 Canvas、Overlay、HorizontalBox，退出时还原。STANDBY/PART 共用只读展示，但各自维护控件实例；只在页面隐藏时还原，不把输入停止当作立即隐藏信号。

补给开始即绑定并隔离本页原生列表/YES-NO 输入。控件树可见、世界正确即可视觉接管，不等 IsEnableControl。SP1/SP2 之后是 YES/NO；YES 等决定键释放，恢复原生视觉树，通过真实 YES 入口完成菜单关闭链。结束事件仅观察，不能主动模拟完成；任务报告补给成功且玩家可用后才应用并保存。

阶段 Actor 的 GetWorld 可能来自流式子关卡：保存阶段实例及其关卡 World，另核对 GameInstance 任务 World，不能直接比较两种 World。离开任务、错误或检查点恢复时清理身份与缓存。补给后的新配置不得用于恢复旧检查点快照。

## HUD 与失败边界

中央为干净 TextBlock，固定正常绿色、局部绿色泛光，字号原生的 10/9；不复制动态颜色绑定或隐藏动画。中央与右下未就绪时亮度为正常 35%，共用只读就绪采样并服从全局显隐。1.0.1 管理参数第 2 版仅中央保留开关，右下固定启用。

武器错误停止修改；UI 错误明确展示与记录，不静默改用其他界面。控件关闭要还原原生状态，不能用吞错继续冒充接入成功。安装器拒绝不匹配的 DLL/Lua/加载器组合。

## 模式识别注意事项

2026-10-15 现场确认：AceUIGameMode_C → UIGameMode → LobbyGameMode → MultiPlayerGameMode。两种父类型都不能单独证明正在进行多人游戏。先拒绝联网世界，再将已知菜单地图中的 UIGameMode 交给页面识别；非共享菜单中的多人类型继续禁止。共享菜单仍检查多人页面和过渡锁定，不等于整张菜单地图无条件放行。详见 1.0.1 候选说明。

当前右下 HUD 与直接选择固定启用，中央简称独立开关；移除未购买兵装试用逻辑。UI 与 Lua 共用 management_protocol=2，配弹仅允许 50% 至 100% 的 5% 档位。profiles.json 的 management_revision=2 标记一次性迁移，机体方案不变。详细迁移规则见[管理说明](mod-management.md)。

## 2026-10-15 第三方模组兼容候选

在 1.0.1 核心/UI 上仅调整 Lua，未升级正式版本。兵装全名读取原生 `Weapon_Name_` 名称表，跟随其当前语言和外部模组内容；缺键或空值仍明确报错，不用简称冒充全名。每页缓存名称，重新进入页面重新读取。

菜单中的武器表编号和实际武器类的 WeaponID 分开处理。选装页面从已加载的 `AcePlayerPawn_<机体代码>` 蓝图默认对象，读取三槽 SpecialWeaponConfig 的武器类默认对象。弹药部件预览、UAV/ECM 禁用及 TLS 收尾依据实际 WeaponID；原生名称、性能条、分类和基础载量仍来自当前加载的数据表。保持购买校验、核心范围保护和原生切换流程。

当前蓝图查找约定已在原版、Adler 和 PW-MKI 文件中核对；尚未保证任意作者自定义蓝图路径、无限弹药或特殊武器生命周期都适用。飞行实测由用户完成，不能把文件分析和语法核对当作通过。批次与恢复说明见[兼容测试安排](research/mod-compatibility.txt)。

同日修订 STANDBY/PART 的生命周期：只读适配器仅拥有自己修改的兵装区域，退出或机体/方案变化时还原这些控件，不改整个页面根节点的显隐。原生负责页面退出和复用；输入暂时停用时保留双栏，等页面隐藏或内容失效再清理。选装页的原生确认交接逻辑保持原样。

第一次尝试在 SetIsEnableControl(true) 中归还隐藏根节点，用户以 Su-57（TGM）→STANDBY→F-14A 再次复现，证明此事件不足以保证归还。两次现场都读到 Review 页面 Visibility=4、根节点 Collapsed，第二次没有恢复事件日志。本次取消只读页的根节点隐藏及相应补救钩子，从所有权上消除遗留隐藏状态；实际菜单复测仍须单独记录，不能用语法核对替代。旧正式代码已有这一根节点隐藏逻辑，尚无证据把本次问题归因于外部模组。

随后用户确认换机 UI 恢复正常，并完成 PW-MKI 替换版双 SP 出击、降落补给与切换。日志支持 100% 配弹下的槽 0+1→2+1 换装；未据此扩大到所有组合、配弹比例和检查点。实际验证范围见[第一批用户反馈](../evidence/compatibility-batch1-user-validation.json)。替换版保留旧名称是外部数据表与武器类分离的实例，名称显示不能作为运行时武器类型判据。

飞控批次新增管理快捷键配置 `management_key`，旧配置缺省为 F8，本机指定 F6。Lua 校验功能键范围及其与武器键的互斥，将字段随管理状态发布；UI 完整校验后更新窗口消息入口、帮助文字和改键排除项。管理保存继续复制完整配置，因而保留入口键。管理协议仍为 2，但此候选 UI 要求新的入口字段，缺失明确报错，不静默换键。飞控原文件保持不变，两个模组分别拥有各自管理界面；实际共存仍需本轮用户验证。

同日 13:51 修订兵装来源：多机体批次暴露出“机体 CDO 必有完整 PlayerWeaponActivator”的假设错误，Su-47 触发组件缺失。当前实现以原生 `GameInstance.HangarManager.LoadedPlayerPlane` 为菜单唯一来源，任务以已绑定玩家机体为来源，核对实际蓝图类和世界后读取三槽组件配置。机库预览实例的 PlaneTypeID 现场为 -1，因此不能靠这个编号挑选预览对象。兵装类 WeaponID 仍从其默认对象读取，不改成菜单编号，也不使用缺失时的猜测回退。前述读取机体 CDO 的候选设计已被替代。

选装、STANDBY 和 PART 的错误属于当前机体上下文；只有用户换机时才写入上下文结束日志并清理这些适配器的错误，避免未安装机体导致后续所有机体停用。保留原错误日志，同一上下文不自动重试。选装页暂存根保留 owner 身份供重进判断；只读页面不隐藏根的修订继续有效。当前只完成语法与离线核对，Su-47 和 PW-MKI 的运行复测待用户。

后续用户已确认 Su-47、独立 PW-MKI 的双 SP、换机、出击和补给正常；当前 53 条目录和 PW-MKI 补给换装日志与之吻合。该反馈更新上段的待验证状态，详见[小批次用户验证](../evidence/compatibility-small-addon-user-validation.json)。未实际覆盖的错误恢复分支、Adler 和其他自定义武器不因此自动标为通过。
