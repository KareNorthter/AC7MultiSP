# 当前架构

对应 AC7MultiSP 2.0.0；完整构建和自动检查通过，已安装，用户已确认本次实测正常。状态与工作规则见 [AGENTS](../AGENTS.md)，工具见[开发说明](development.md)；用户键位与操作不在此重复。

## 修改定位

| 文件 | 职责 |
|---|---|
| dist/DualSP/Scripts/main.lua | 游戏线程调度、世界/玩家、出击/补给/检查点、管理暂停与调试 |
| config_store.lua | 配置迁移、设置校验、上一份备份与保存；不持有游戏对象 |
| native_bridge.lua | 原生命令协议3、请求号、应答匹配；不决定玩家身份和HUD时序 |
| loadout_profile.lua / loadout_flow.lua | 1–3 槽校验/均分；出击与补给草稿、光标和确认 |
| native_loadout.lua | 准备/补给/STANDBY/PART 布局、输入交接及控件归还 |
| runtime_context.lua / weapon_cycle.lua | 单人许可与语言；MSL/SP 循环和耗尽跳过 |
| native_hud.lua / weapon_presentation.lua / weapon_names.lua | 右下固定行和剪影；中央提示与简称 |
| json.lua | 配置和状态序列化 |
| src/weapon_bridge.cpp | 原生重建、弹药/冷却、输入/音效及检查点 |
| src/su30sm_fixed_mount.hpp | 三机型规格、模型显隐、实际离架、活动挂架和舱门 |
| src/overlay.cpp | 管理 UI、直接输入、只读状态与动作队列 |

Lua 表内短文件名均位于 dist/DualSP/Scripts。挂载头文件仍包含在核心私有命名空间中，复用共同类型与原生访问函数；核心通过 before/after rebuild、record reload、update 接口交接，不再直接读写其内部挂载或舱门状态。未拆成独立编译单元。
专用 UE4SS 提供游戏线程定时与 Lua/原生桥接；渲染线程只能读状态/排动作，不能操作引擎对象。

## 数据与配置

原生草稿 → 真实确认交接 → 机体方案 → 游戏线程核心会话 → HUD。短事务带请求编号；常规 HUD 采样不周期写完整武器快照。
逻辑选择 0/1/2/3 是 MSL/SP1/SP2/SP3，原生武器配置只有 0/1/2；挂架池编号和物理挂点另有机型映射，不能因数量/顺序不同而直接统一。名称按原生表显示，行为按实际武器类判断。

| 契约 | 当前规则 |
|---|---|
| 个人配置 / 管理 | schema=2；management_revision=3；management_protocol=3。UI 状态自身 schema=1 是另一结构 |
| 方案与载量 | a/b/c 连续且不重复，空槽 -1；先计部件再按数量均分取整，正载量至少一发，零仍零 |
| 设置 | language=auto/zh/en，central_hint 保留开关，keyboard_keys 默认 [49,50,51,52]，management_key 缺省117（F6）、保留显式旧值 |
| 迁移 | schema 1 先保存 profiles.before-three-sp.json，补空第三槽与数字4键，移除 ammo_ratio；旧键占用4或备份冲突明确拒绝 |
| 提交 | 设置校验和写盘成功后生效，不用默认值替换错误；普通保存与应用调试方案分开 |

配置和 UI 状态先完成 JSON 编码再打开文件，写入及关闭失败明确上报；配置备份失败则不覆盖原文件，主文件写入失败时保留上一份备份，不宣称具备断电原子恢复。原生命令同样检查写入和关闭，失败不调用核心消费残缺命令。

直接选择只响应按下边沿；装填中可选，未选/耗尽 SP 跳过。暂停、补给、未就绪或事务中不存延后请求。
中央简称可关闭，右下 HUD/直接选择固定启用；未就绪变淡，服从原生全局显隐。日志页按需读取末尾片段。

页面构造使用具名依赖，更新使用 instance/planeId/getProfile/getOptions/now/inFlight/panelOpen；reset 明确标注 clearError/releaseInput。四页各自保存控件/事务，内部布局和原生确认流程保持原样。main 的 pageContext 集中提供出击、只读已保存方案和补给方案三种来源。

## 生命周期与失败边界

- main 的 resetFlightTracking 只清运行缓存，不释放原生对象或取消补给；resetCheckpointState 清检查点与调试标记。换玩家时仍在补给事务中则保留检查点；完全禁用模组时一并清理，状态不能带回下一次启用。
- 出击按 SP1、可选 SP2/SP3 顺序确认；空槽结束后续选择，真实原生动作交接到 STANDBY，确认前不保存。
- 补给绑定页面/玩家并隔离单 SP 输入；最终 YES/NO 默认 NO。真实原生起飞成功后才重建、保存、提交 HUD，不伪造完成事件。
- 切换先保存独立库存/装填队列及游戏时间，重建后恢复；保留普通弹药、机炮和干扰弹，最终选择/HUD/音效同次提交。
- 检查点独立保存方案及会话；后续补给/调试不能覆盖旧检查点，也不能用新方案恢复旧快照。
- 调试只重配并补满 SP，选回 MSL；保留普通弹药、个人方案及旧检查点，新检查点可记录调试方案。活动武器未结束要拒绝，当前登记为空并非完整追踪所有旧弹体的证明。
- F6 只释放自己取得的暂停，原有暂停保留；失败可见，不能强行清零。离页/换世界归还自有控件、输入和缓存，STANDBY/PART 不隐藏整页根。
- 机库取实际 LoadedPlayerPlane，任务取实际玩家，核对类继承/世界/组件；固定挂载另核对对象索引和序列号。旧地址不能跨任务/进程复用。
- UIGameMode 也继承多人父类型，不能单凭 LobbyGameMode/MultiPlayerGameMode 判多人；先核对联网状态、已知菜单与页面，模式变化清事务。
- 正常加载用等待/占位，10秒超时明确报错并允许原生恢复，不伪造数据。未知机型可用原生模型，已匹配机型身份异常不能伪装成未适配。

## 挂载约束

兵装库存/发射窗口、模型池/物理位置、动画/持续效果分别拥有生命周期，数量不能互相替代。显示与真实离架共用映射，活动点取实时世界变换；重建前解绑、之后重绑。

| 机型 | 必须保留的规则 |
|---|---|
| Su-30SM | LAGM 六槽、两枚窗口；备用库存不能提前填回补装中的空位。三挂外翼QAAM/内翼6AAM/机腹LAGM，其他组合独立布局 |
| F-35C | SWP2 保留原父链、Socket、Tick和动画；SOD+4AAM 的两个活动位置轮转六槽、四发窗口不变；8AGM 十二槽/八发窗口分开理解 |
| F-15E | TLS 空网格组件是发射点，炮体在挂架内；冷却/耗尽不隐藏炮体。TLS→MSL 已验证，跨SP仍收尾 |

初始化同步 PlaneSWP 和飞行引擎编号，单挂也相同。F-35C 完整执行原生动画，补齐非当前通道收拢；同舱切换继承进度，退出归还最近原生请求，不永久开舱或冻结骨骼。
机库/演出实例不能复用任务身份；补给、调试、检查点也不能跨任务继承动画。不得只删 TLS 收尾就声称支持持续效果，重建还会清理归属与引用。

扩机型先确认可选性、真实武器类、运行池/窗口、父链、骨架和重建行为；F-22A 不能套用 F-35C 偏移/通道。
每架准备三单挂、三双挂和三挂，保留美观、真实发射空位、装填、锁定/齐射和性能；调试七组合不能替代原生补给、检查点和长时实玩。

## 工程入口

产品名和 Lua 清单统一登记 src/product.json，版本唯一文件 VERSION；内部 DualSP 目录、DLL 导出和配置协议保持兼容。
src/build.py 全量构建，release_tools.py 共用来源与路径校验，install.py 使用显式前版运行文件回执；不再导入退役研究安装器。
构建回执保存全量产品源/头文件/第三方文件摘要、命令、工具链整树指纹；安装核对旧回执对应的实际 Lua 集合后，允许新增已登记模块；移除旧模块须明确迁移，不能遗漏未登记文件。安装和打包重新计算源码集合，新增、删除或修改均拒绝。测试回执绑定构建回执和测试源码。
