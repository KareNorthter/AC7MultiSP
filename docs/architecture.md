# 当前架构

基线为已实测AC7MultiSP 2.0.0。当前2.4.0整合可配置快捷键、三机型修订布局和ADFX-01持续武器实验，已完整编译、通过适用检查并安装，新功能待用户实测。游戏已安装2.4.0；用户已确认其快捷键正常，新布局和持续效果仍待实测。状态与规则见[AGENTS](../AGENTS.md)。

专用 UE4SS 提供游戏线程定时与 Lua/原生桥接；渲染线程只能读状态/排动作，不能操作引擎对象。

## 数据与配置

原生草稿 → 真实确认交接 → 机体方案 → 游戏线程核心会话 → HUD。短事务带请求编号；常规 HUD 采样不周期写完整武器快照。
逻辑选择 0/1/2/3 是 MSL/SP1/SP2/SP3，原生武器配置只有 0/1/2；挂架池编号和物理挂点另有机型映射，不能因数量/顺序不同而直接统一。名称按原生表显示，行为按实际武器类判断。

配置和 UI 状态先完成 JSON 编码再打开文件，写入及关闭失败明确上报；配置备份失败则不覆盖原文件，主文件写入失败时保留上一份备份，不宣称具备断电原子恢复。原生命令同样检查写入和关闭，失败不调用核心消费残缺命令。

直接选择只响应按下边沿；装填中可选，未选/耗尽 SP 跳过。暂停、补给、未就绪或事务中不存延后请求。
模组启用时中央简称、右下 HUD/直接选择固定启用；未就绪变淡，服从原生全局显隐。总开关关闭后仅保留管理入口与其暂停/输入交接，核心许可关闭，原生出击、补给、HUD、切换和挂载不被接管。多人限制仍优先。日志页按需读取末尾片段。

未确认草稿读取最新百分比；出击/补给确认与调试生成独立比例快照，普通保存不补充当前库存。核心命令4在 request 后携带 ratio，会话和检查点独立保存。菜单和核心都用整数公式 `(完整载量×百分数+99)/100` 向下取整实现向上取整，避免小数误差。检查点恢复不套用之后保存的管理比例。

选装、补给和待命标题采用24号；准备页的三条 SP 弹药行使用独立 Canvas，当前逻辑槽全亮，其他两行信息蓝半透明，不继承原生武器编号高亮。中央提示相对原位置上移半个字高。

页面构造使用具名依赖，更新使用 instance/planeId/getProfile/getOptions/now/inFlight/panelOpen；reset 明确标注 clearError/releaseInput。四页各自保存控件/事务，内部布局和原生确认流程保持原样。main 的 pageContext 集中提供出击、只读已保存方案和补给方案三种来源。

## 生命周期与失败边界

- main 的 resetFlightTracking 只清运行缓存，不释放原生对象或取消补给；resetCheckpointState 清检查点与调试标记。换玩家时仍在补给事务中则保留检查点；完全禁用模组时一并清理，状态不能带回下一次启用。
- 出击按 SP1、可选 SP2/SP3 顺序确认；空槽结束后续选择，真实原生动作交接到 STANDBY，确认前不保存。
- 补给绑定页面/玩家并隔离单 SP 输入；最终 YES/NO 默认 NO。真实原生起飞成功后才重建、保存、提交 HUD，不伪造完成事件。
- 切换先保存独立库存/装填队列及游戏时间，重建后恢复；保留普通弹药、机炮和干扰弹，最终选择/HUD/音效同次提交。
- 检查点独立保存方案及会话；后续补给/调试不能覆盖旧检查点，也不能用新方案恢复旧快照。
- 调试只重配并补满 SP，选回 MSL；保留普通弹药、个人方案及旧检查点，新检查点可记录调试方案。活动武器未结束要拒绝，当前登记为空并非完整追踪所有旧弹体的证明。
- F6 只释放自己取得的暂停，原有暂停保留；失败可见，不能强行清零。离页/换世界归还自有控件、输入和缓存，STANDBY/PART 不隐藏整页根。
- 机库取实际 LoadedPlayerPlane，任务取实际玩家，核对类继承/世界/组件；固定挂载另核对对象索引和序列号。旧地址不能跨任务/进程复用。
- UIGameMode 也继承多人父类型，不能单凭 LobbyGameMode/MultiPlayerGameMode 判多人；先核对联网状态、已知菜单与页面，模式变化清事务。
- 正常加载用等待/占位，10秒超时明确报错并允许原生恢复，不伪造数据。未知机型可用原生模型，已匹配机型身份异常不能伪装成未适配。

## 挂载约束

实验挂载开关只控制三架已适配原版机型，其他机型仍走原生单 SP 模型。启动默认关闭核心接管，由 Lua 显式设置；关闭后不接管显隐、发射取位或 F-35C 动画修补。菜单保存可直接更新开关；任务内保存只记录待应用值，在下次出击、重启任务、检查点重试、补给成功或显式调试换装的原有武器重建边界应用，无需重启游戏。保存本身不重建武器、不补弹；管理页区分模型待应用和总开关待重启。

外观异常与兵装事务分开：失败停止本次模型接管，逐组件归还最近原生显隐/挂架动画请求；单项恢复异常不阻断其余项，待恢复项保留对象身份继续归还，失效对象不再解引用。警告进入管理页，不将已成功的武器事务改报失败。该回退路径尚未经实机验证，不能保证损坏或失效对象可被强行恢复。

兵装库存/发射窗口、模型池/物理位置、动画/持续效果分别拥有生命周期，数量不能互相替代。显示与真实离架共用映射，活动点取实时世界变换；重建前解绑、之后重绑。

| 机型 | 必须保留的规则 |
|---|---|
| Su-30SM | 单QAAM按库存显示sp21–24四处，窗口仍为2；按用户选择，多挂QAAM恢复sp23/24及SWP3共用导轨。QAAM+6AAM恢复内翼/机腹四处6AAM；三挂恢复内翼两处6AAM、机腹两处LAGM。QAAM+LAGM两处QAAM加四处LAGM填满六处共用支架 |
| F-35C | SWP2保留原父链、Socket、Tick和动画；按SOD发射穿插反馈，SOD+4AAM恢复仅sp25/26两处，六槽和四发窗口不变。移除四活动点的窗口分配逻辑；8AGM仍按库存最多显示十二处，八发窗口不变 |
| F-15E | 同选6AAM/SFFS时，外翼sp11/12两枚导弹保留；其余四枚的显示和离架使用外排sp21/22/25/26，SFFS十二槽映射内侧sp27–32六处。外排前后两对使用导弹网格，中间sp23/24隐藏；原SWP1机腹四枚隐藏。其他组合、原生窗口和TLS规则不变 |

本轮缩减的是可见/发射位置，不修改原生逻辑槽数、锁定数、齐射数量或冷却。预览与任务使用同一位置映射。8AGM、单QAAM和SFFS的备用模型按实际库存显示；原生把补装计时移到新窗口槽时，回溯其替代的已发射位置，保持该处空位到补装完成，实际就绪弹优先。

F-15E交换复用现成StaticMeshComponent及其原生Socket，通过加载器公开ProcessEvent调用SetStaticMesh，同时改变外观与取位，不直接写网格指针，不新增游戏资产。调用前验证加载器导出、函数对象身份/所属类及参数数目/类型/大小/偏移；不匹配即独立回退。任务与预览各自保存原网格身份，候选变化、单多切换、机库组件重建、失败和退出时逐项归还；归还失败保留对象身份重试，恢复任务前重新应用其布局。同步渲染回调期间不重复替换网格。

研究边界见[几何与布局记录](../evidence/mount-layout-research-latest.json)：用户报告F-15E下落段穿过SFFS、F-35C新增两处4AAM穿过发射中的SOD、Su-30SM缺导轨/出现空架，作为布局修订依据，不扩大为本分支新源码已实测。新网格替换调用仅离线核对了加载器导出，参数布局在运行时检查；本轮没有编译、运行测试或操作游戏，仍需核对离架下落、补装、材料/边界更新及场景归还。

初始化同步 PlaneSWP 和飞行引擎编号，单挂也相同。F-35C 完整执行原生动画，补齐非当前通道收拢；同舱切换继承进度，退出归还最近原生请求，不永久开舱或冻结骨骼。
机库/演出实例不能复用任务身份；补给、调试、检查点也不能跨任务继承动画。不得只删 TLS 收尾就声称支持持续效果，重建还会清理归属与引用。

扩机型先确认可选性、真实武器类、运行池/窗口、父链、骨架和重建行为；F-22A 不能套用 F-35C 偏移/通道。
每架准备三单挂、三双挂和三挂，保留美观、真实发射空位、装填、锁定/齐射和性能；调试七组合不能替代原生补给、检查点和长时实玩。

## 组合调试与全场景模型快捷键

2.4.0三个动作均可在按键页设置单键或Ctrl/Alt/Shift组合。窗口输入以完整修饰键精确匹配，单键与同主键组合不互相触发；不接受独立修饰键、Esc、Alt+F4或Ctrl+Alt+Delete。三个动作不能重复，单键动作不能占用四个武器直接选择键；带修饰键可共用主键。捕获优先于动作，连发/释放一并消费，失焦重置；设置草稿不改变输入，保存应答发布后原子替换三组运行键。配置与UI互验管理协议6，新UI导出握手拒绝混装。

2.3.0由游戏窗口接收Ctrl+Alt+F6/F7，处理普通与Alt系统按键消息；按下只触发一次，消费连发和释放，优先于普通F6管理入口。渲染线程仅入队，携带独立请求号、任务session和兵装revision；F6在游戏线程重新校验许可、机体、飞控、补给/检查点交接及在途武器，不接受过期请求，不自动排队重试。F7仅校验协议和独立请求号，不套用换装守卫或旧兵装版本；同一请求只能切换一次。

Ctrl+Alt+F6按A→B→C→AB→AC→BC→ABC轮切，集合忽略排列顺序；以当前实际方案为起点，跳过未购买、UAV/其他ECM等仅单挂限制，没有其他组合时只提示。复用debug_setup完整事务，按已保存比例补满SP并回到MSL，保留普通导弹、机炮、干扰弹、个人方案和已有检查点。正常飞行不需打开面板或暂停，管理面板打开时仍遵守其暂停拥有权。

Ctrl+Alt+F7先保存实验开关；机库按最后候选立即刷新，补给页由预览同步，补给确认后可凭同一任务玩家和已确认快照重建预览。没有有效机体或正在检查点重建时先保存设置，既有重建路径按新设置绑定；总开关关闭时只保存。已配置任务中不要求飞控开放、解除暂停或清空在途武器，调用dualsp_debug_fixed_mount(plane,activator,time,enabled)即时释放或重新绑定当前实际挂载与动画。该入口不初始化兵装、不捕获或改写session/checkpoint、不补弹，不改变活动SP；关闭归还原生请求，开启仍只支持已适配三机型，绑定异常仍独立回退。正常管理保存仍沿原有重建边界生效，快捷测试入口单独即时应用。界面短提示展示结果/拒绝原因，管理调试页说明快捷键，开关草稿同步实际保存值。

## 机库与补给动态模型预览

2.2.0接入随草稿变化的模型预览；2.2.1把显示所有权扩展到场景与起飞过渡，2.2.2补齐页面激活和原机体组件重建，与实验多挂开关共用许可。预览状态独立于实际兵装，任务库存、冷却、队列和发射映射不随光标变化。2.2.0用户实测确认候选可以改变模型，但STANDBY→PART闪回、SKIN及出击/补给起飞漏接。日志确认补给YES约1秒后页面失效触发预览回退，再过约9秒才完成兵装重建；不能视为全流程通过。2.2.2修复后用户实测反馈“基本没看到问题”，具体场景覆盖范围未逐项列出。机库的实际展示对象是 `HangarManager.LoadedPlayerPlane`；现有 main/optionsFor 已处理异步换机、真实类链和 World，预览机的 PlaneTypeID 可为 -1。准备页 paint 调用 `dualsp_preparation_action(...,3)`，核心转到原生 CursorChanged（本 build RVA 0x6d4590），只更新当前一个 SP 的模型和镜头；EMPTY 保留 SP1。完整候选方案已经由 `Flow:preview()` 提供，作为多模型展示输入。

2026-10-16 对 F-15E 机库 STANDBY 的只读现场采样确认：实际对象为 AcePlayerPawn_f15e_s06_C，SWP1/2/3 均挂在 WeaponMeshBase 下，根挂架没有 Socket，子武器使用 spXX。SWP1 有六个 sp11–sp16 武器网格，SWP2 有十二个 sp21–sp32 武器网格；SWP3 的 sp31 武器网格为空，TLS 炮体由挂架承载。当前原生选择 SFFS，只有 SWP2 可见。此结果证明该机库实例的三组模型同时存在，不证明动态多挂预览已实现；采样当时是 STANDBY，共享弹药行层级已核对，未采到 SP 选择页或补给可见对象。

准备页弹药行必须保留根 Canvas 与 CanvasPanel_2 的中间布局，再从文字运行时包装层提取外侧 Canvas 槽。2.1.0 把该槽误当直接位于根下，触发保护并回退原生；2.1.1 按实际 Canvas 祖先链复制空容器，保留根归属检查及失败清理，不修改原生源控件树。

2026-10-16 的 ms06/F-15E 补给现场确认：页面 +0x5c0/+0x5c8、控制器 Pawn、摄像机 ViewTarget 均指向任务玩家及其武器组件；所有现场 F-15E 模型组件也归属于该玩家，没有发现另一架展示替身。MiniGameCameraComponent 的 DummyCameraActor 只是镜头对象。结论限定这次任务、机体和补给实例，不能替代其他机体/任务的核对。

现场 SP1 草稿只有6AAM，组件却仍显示两处外侧6AAM、十二处SFFS及TLS挂架，与进补给前日志掩码0x3ffc3一致。原因已由源码闭合：补给开始保留 fixedMount.bound；supplySession 阻止周期 fixedMountRefresh，但显隐钩子仍按旧 rackMask/readyMask 拦截原生请求。paintSupply 只更新文字、性能及配弹，不调用模型接口。故单独调用 SetVisibility 会被旧接管覆盖；不能把停止周期刷新当成已经释放模型。真正兵装重建仍在原生补给成功后执行，悬停时不能调用 setup/resupply_setup/InitializeWeaponSystem。

同次补给由用户手动将SP1候选切至SFFS后，画面文字及预览弹药已变为SFFS/46，日志记录sp1光标2。第二张只读快照确认三挂架和十九武器组件的身份、父链、Socket、网格、相对变换和显隐均不变；实际活动武器仍为6AAM/SWP1，原生命令与状态文件未变。该对照确认候选变化未驱动模型，也没有在该步骤销毁或替换组件；没有直接读取全部库存和冷却，不能扩大为完整兵装状态验证。

实现抽取三机型共用的只读布局规则，并使用独立预览上下文，按场景拥有者、世界、实际展示对象和组件索引/序列号绑定。只控制经过核对的持久模型显隐，不接管发射取位、不修改库存或冷却。机库保留原生光标镜头联动，模型池稳定后再叠加完整候选；机库由游戏实例持有预览，并持续核对HangarManager.LoadedPlayerPlane；所有原生菜单激活事件均在返回前刷新当前机库方案，控件改造仍只限登记页面；活动选装页草稿优先，其余页面（含STANDBY/PART/SKIN/EMBLEM）统一使用保存方案。离开单个页面不归还整个机库显示；展示机改变时重新校验绑定，离场、身份异常及关闭实验开关才归还原生状态。

原生接口 dualsp_mount_preview 接收场景拥有者、展示飞机、武器组件、模式、三个原生SP索引及配弹数量。模式1为机库；模式2由补给页接入并转由同一任务玩家持有；模式3为已被PlayerController持有的开场玩家机体；模式4只巡检既有补给预览，不能新建绑定；模式5用于补给确认后F7重启预览，owner必须为当前session的玩家，并核对激活器/世界，使用Lua保留的确认快照；模式0按owner归还，世界变化/重建才允许全释放。页面更新不依赖文字绘制签名；未开放输入的开场仅显示保存方案，不提前初始化任务兵装。开场与重启先经GameplayStatics.GetPlayerPawn取得当前玩家，绕过250ms的全局扫描等待；未持有玩家时保留低频发现。玩家控制器尚未持有飞机时等待，演出替身不接管。预览警告单独交给管理页，不把失败变成页面错误或中断补给。真实错误锁定当前场景/机体身份并退回原生显示，不随光标反复接管；未归还项（包括补给起飞过渡）每200毫秒只重试恢复，异步空池则等待就绪。稳定候选缓存解析结果，每100ms巡检对象和模型池身份；候选改变与原生显隐钩子立即处理。同一机库飞机若重建了管理器、根组件、挂架或模型池，先完整校验新布局，再继承仍为同一索引/序列号组件的原生请求；复用组件不先归还单挂，新组件不继承旧祖先隐藏或动画状态。原生总显隐钩子能识别当前激活器的新模型管理器，在原生更新返回前重新接管；空池加载阶段等待，结构不符仍锁定回退。补给和任务实例不套用这一机库重绑策略。F-35C保留骨架父链与原生动画；未知资源、模型池或Socket不套用近似布局。

候选变化使用 Flow:preview：前置已选加当前候选，EMPTY截断后槽；review显示完整方案，NO返回SP1重新预览，返回上一槽也重算。预览按候选配弹后的装填/备用模型规则显示，复用任务位置映射，不按总库存创建额外组件。F-15E同选6AAM/SFFS显示外翼两枚导弹、外排前后两对导弹和内侧sp27–32六枚炸弹及两套挂架；TLS炮体来自SWP3挂架，空网格sp31不是缺失错误。6AAM+TLS保留原六处导弹布局，组合不受选择顺序影响。

YES后把预览转为已确认过渡状态，原始页面不再是存活条件，持续核对原任务session、玩家/激活器/世界及组件身份，服从原生过场显隐；到补给成功、原有 configureFlight 即将重建时先释放预览，再由新任务挂载接管，避免菜单关闭到起飞间闪回旧组合。退出事务、检查点重试、换世界、异常或禁用必须释放预览并按当前有效身份归还；显示失败独立降级，不能提前提交草稿或改动弹药。机库与补给共用实验开关、纯布局规则和原生单SP回退。

场景检查边界：暂停、地图及镜头切换保留已有任务挂载；任务重启/换世界释放旧实例，新玩家按开场路径接入；检查点与补给成功继续由原有同步兵装事务重建，不提前改变库存或冷却。换机/换涂装新实例由LoadedPlayerPlane重新定位，原实例重建组件则走上述完整重绑。失效身份、关闭实验开关及不支持的模型仍须归还原生。尚未证明新机体首次绘制前一定接管，也未识别独立演出替身；不能声称全部过场零单挂帧。

## ECM/TLS 持续效果研究

目标是发射后立即换另一种SP，同时让原效果按原生规则继续到结束。2.0.1研究候选已写入ADFX-01实验源码：原生IEWS可与TLS/MPBM多挂，两种持续效果尝试跨SP保留。尚未编译或执行跨SP实测；其他ECM/UAV和其他机型TLS沿用2.0.0限制。

### CFA-44 ECM 的现场机制

2026-10-16用户用CFA-44搭载IEWS发射并手动暂停。实际类为 `plwp_ecmp_x1_C → plwp_esm_x0_C → ElectronicSupportMeasures → WeaponBase`，实际WeaponID=31，不能根据菜单名称推断替换机模的行为。四次暂停对照保留同一对象索引和序列号：

| 阶段 | 对象累计时间 | 玩家SupportMeasures | ActiveWeapons | 冷却进度 |
|---|---:|---|---:|---:|
| 发射后 | 2.087秒 | 指向该ECM | 1 | 2.087／42秒 |
| 切MSL并飞行后 | 7.071秒 | 仍指向同一ECM | 1 | 7.071／42秒 |
| 雷达范围消失后 | 27.108秒 | 空 | 1，对象仍活动 | 27.108／42秒 |
| 再飞行约5秒 | 对象停在30.003秒 | 空 | 0，对象非活动 | 32.089／42秒 |

现场默认值为SupportTimeCampaign=JammingTimeCampaign=26秒、LifeTime=30秒、LoadTime=42秒、EffectRangeMeter=3200米。支援与干扰开关均为真；bReloadOnFire=true、bReloadAfterAllFired=false、bSwitchWeaponOnLastDestroyed=false。因此该ECM发射即开始装填，26秒作用结束不等于30秒对象退场；退场后SpawnedWeapons仍保留该对象，不能把“仍能读到对象”当作仍有干扰。没有测量敌方导弹命中率或伤害变化，玩家支援引用和雷达表现不能代替完整干扰效果验收。

用户观察圆形雷达范围跟随机体。MSL后快照中ECM根组件位置与飞机根组件位置相同；原生Tick `0x86c020` 每帧从OwningGameObject的根组件取位置，再更新ECM位置。它不使用TLS的AttachedComponent/Socket结构。暂停前后计时连续，未出现重新发射或重新计时；这证明本次MSL路径，尚未证明跨另一SP的重建路径。

作用判定不只依赖当前SP：`0x7fe240`调用链从世界相关对象集合取得活动ElectronicSupportMeasures，重新计算各GameObject的JammingMeasures(+0xb20)和SupportMeasures(+0xb28)。`0x86bc00/0x86bc90`分别检查干扰/支援开关、单人时长、阵营关系和距离，并按效果优先级选择来源。`0x4e3be0`从类相关对象集合筛选活动标志与对象有效性，不能把此集合等同于玩家激活器的ActiveWeapons。效果超时后原生重新计算会撤销引用；不应由模组永久写死目标增益或雷达圈。

### 与TLS共用和不同的部分

两者都使用WeaponBase的活动标志、计时及原生收尾，且结束可回到当前玩家激活器。但玩家TLS实际属于AttachedInstantWeapon；不能使用LaserWeapon的Tick作为玩家TLS判据。TLS原生 `0x85e090` 从自身根组件读取位置、朝向生成伤害射线。让可见光束继续显示却没有正确附着，可能让伤害留在旧位置。

本次用户随后改用Morgan，现场识别为AcePlayerPawn_mrgn_C及plwp_tls_x1_C。活动TLS在1.224秒时bReloadOnFire=true、bReloadAfterAllFired=false、bSwitchWeaponOnLastDestroyed=true，冷却已推进1.224／10秒，LifeTime=8秒；10秒是当前安装环境的有效值，不覆盖原版离线资源13秒的记录。该TLS同样不需要等待结束才启动装填。实际RootComponent为Static Mesh，依次附着到SWP1、WeaponMeshBase、飞机RootComponent；AttachedComponent也指向SWP1，Socket为sp11。用户切MSL并轻微转弯后，同一TLS对象计时与冷却连续到3.181秒，所有父链组件索引/序列号保持，根组件位置随飞机改变。此时owner+0x158的SP组件组为空，普通组只有一个ParticleSystemComponent，TLS附着父链不属于该清理列表。因此不能把该临时组件池销毁当成本次Morgan光束固定的已证根因；仍须观察跨SP重建中的真实解绑、挂架变换与显示管理行为。没有实测光束伤害与最后一发自动切换。

现有跨SP路径先结束TLS，再缓存弹药/冷却，最后调用InitializeWeaponSystem重建。原生 `0x884f10`清空SpawnedWeapons/ActiveWeapons等列表，`0x89da40 → 0x89bc40`重建组数组。须严格区分结构：owner+0x158是嵌套组件数组，本次ECM现场普通兵装组包含ParticleSystemComponent、SP组为空；当前SP组+0x48是WeaponParameters，均不能称作活动武器Actor池。组件清理调用的是组件虚表+0x360，现场入口 `0x16e3e80`最终可进入组件撤销/标记待销毁路径；不能拿Actor同虚表槽的RootComponent getter解释它，也不能把已清理组件的旧地址重新写回TLS。

共用结束回调 `0x894850 → 0x885240`先移除活动对象，随后读取**当前SP**默认对象与弹药。即使ECM自己的bSwitchWeaponOnLastDestroyed=false，回调仍可能调用 `0x8860f0`停止当前SP的连续声音/组件状态；因此“ECM冷却正常”不足以证明跨SP安全。TLS最后一发的自动切换还需按其源槽决定，不能受新SP库存控制。

条件式冷却收尾 `0x897010 → 0x89e3c0`使用旧对象保存的owner/group/slot访问当前组。重建后同一编号可能已经属于另一SP。现场CFA-44 ECM和Morgan TLS的bReloadOnFire=true且相关owner为空，不走等待结束启动装填的路径。其他TLS活动变体的标志仍须现场读，不把基类CDO或“持续武器”一概视为等待结束装填。

### ADFX-01 实验实现与验收边界

实现位于 `src/continuous_sp.hpp`，由核心 initialize 换槽事务接入。Lua 选装只对 mrgn 的 WeaponID=31 请求新具名接口核验；同时核对机体继承包、真实武器类包、原生收尾虚表及发射即装填标志。范围限定 `plwp_esm_x0_C` 和 `plwp_tls_x1_C`；不因第三方使用相同菜单名称而放开。ADFX-01原生另一个SP为MPBM（多用途爆破导弹）。不修改ECM的作用时长、范围、对象自身Tick或支援白名单，TLS不因此获得ECM增益。

跨SP前从SpawnedWeapons筛选仍活动的已核对发射体，包含已离开ActiveWeapons的TLS尾迹。来源保存对象索引/序列号、机体/激活器/关卡身份、源逻辑槽、年龄和原生退场标记；不保存整个旧数组，不恢复已退场历史对象。同步重建空窗内，用FUObjectItem内部RootSet临时保有Actor；按原值记录所有权，使用原子位操作且只撤销本次新增的位。RootSet不是对象复活手段，也不能阻止原生销毁；仍须核对重建后身份、发射代次与附着。

重建后重新检查两份原生数组的data/Num/Max和所有缺项容量，写入缺项后提交Num，不复制TArray头、不换原生分配器、不扩Max。活动效果恢复ActiveWeapons与SpawnedWeapons；已结束伤害的尾迹只恢复SpawnedWeapons。强引用恢复后在同一调用栈释放临时root，长期记录只持弱身份。原生对象池是否在所有切换边界重用对象仍需实测，校验失败不能强写活动位继续。

结束隔离有两处：`0x885240`移除旧效果的ActiveWeapons登记后跳过当前SP策略；`0x885510`跳过旧效果对当前SP的退场通知。后者由 `0x897740` 调用，也可能经 `0x8860f0` 停止当前SP声音/组件，所以只隔离前者不够。Actor自身的结束、ECM撤销、TLS尾迹、隐藏、停Tick与原生退场继续执行。已经跨过重建的旧发射代次一直隔离，即使用户切回源逻辑槽，也不能让旧效果结束后来发射的同类效果；旧代次不会强迫当前武器自动切换。两处通知内不删来源记录，后续游戏线程确认对象非活动或身份失效才清除。

现场两类均发射即装填，沿用原有各槽冷却缓存；不将对象地址写入检查点。补给/同玩家重新建立组合/检查点恢复前结束本模块保留的效果，调试换装等待持续效果和尾迹退场。换世界后身份不再匹配，弱记录不复用于新玩家；关闭单人功能后旧对象通知仍可只完成既有登记隔离，不因清空session误用当前槽。

TLS保存原有Root→SWP1→WeaponMeshBase→飞机根组件链与Socket，重建后核对，没有新造锚点、重跑激活或每帧伪造位置。正常TLS尾迹可持续2秒；失败回退在临时root释放前先请求原生结束，再通过已核对的虚表+0x680完成剩余尾迹退场。容量、身份或附着异常通过既有核心错误回执停止控制器；应退出任务后检查日志，不能把失败视作保留成功。RootSet不计引用数，同步区间仍未覆盖第三方并发改root等兼容情况。

实测按ADFX-01进行：IEWS→MPBM并发射、IEWS→TLS并发射、TLS→MPBM、TLS→IEWS，再快速往返及切回同源槽；核对范围跟随、目标支援/干扰、光束方向与真实伤害、原始寿命、各槽弹药/冷却、尾迹与最后一发。随后检查补给、调试拒绝、死亡、任务重启和检查点。模型显示、连续声音和真实伤害均待跨SP验证；保留对象与附着通过不等于这些表现已通过。

诊断事件为CONTINUOUS_CAPTURED、CONTINUOUS_RETAINED、CONTINUOUS_RELEASE_ISOLATED及CONTINUOUS_RETIRE_ISOLATED；异常用CONTINUOUS_*_ERROR和既有NATIVE错误回执记录。本轮仅静态审查，没有编译、自动测试、安装或操作游戏。此前MSL采样及原生调用链见[研究证据](../evidence/ecm-tls-persistence-research.json)，不能把它们写成此实现的验证结果。
