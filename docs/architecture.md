本文说明已验收主线 AC7MultiSP 2.19.0及当前2.19.2整合候选。在2.18基线`0991906`上接收`f4bb86c`炮口查找和计时修订，用户已确认有效、卡顿明显减少并授权合入。其他功能沿用2.18，主线确认后用户另授权制作2.19.0发布包，沿用相同已测字节，不重新构建或安装。版本交付与安装定位见[开发说明](development.md)、[版本说明](release.txt)和[安装说明](安装说明.txt)。

2.17反馈ECM模型不再显示，切ECM时ADMM/EML展开可以接受；2.18反馈切换仍明显卡顿，2.19用户确认明显减少；不表示完全无卡。用户另反馈任务结算界面箭头卡顿明显缓解，仍有轻微卡顿；此项与选装光标卡顿分开记录。2.16已知的ADF-01停光卡顿继续保留。以上不表示所有机型、七组合、任务和故障路径均已验收，后续源码处理CFA重复开合及用户指定的FALKEN自然停光等待，两者连同默认关闭的镜头保持功能已接收至2.19.1候选，实际效果待用户实测。

## 模块职责

Lua 在游戏线程确认模式、世界、实际玩家及原生交接，再向核心提交事务。核心管理兵装会话和独立视觉状态；渲染线程只读取状态、绘制界面和排队动作，不操作游戏对象。

| 文件或模块 | 职责 |
|---|---|
| `dist/DualSP/Scripts/main.lua` | 游戏线程调度、玩家与世界、出击/补给/检查点、许可和管理暂停 |
| `debug_aircraft.lua` | 官方机体调试列表、原生完整任务重开、实际新玩家确认、任务临时方案 |
| `config_store.lua`、`loadout_profile.lua`、`loadout_flow.lua` | 配置迁移/保存，三槽与比例校验，独立草稿和确认流程 |
| `native_loadout.lua` | 准备、补给、STANDBY、PART 的原生控件、输入交接和归还 |
| `runtime_context.lua`、`weapon_cycle.lua` | 单人许可、游戏语言、MSL/SP 循环与耗尽跳过 |
| `native_bridge.lua` | 请求编号、原生命令与应答匹配，不自行决定玩家身份 |
| `native_hud.lua`、`weapon_presentation.lua`、`weapon_names.lua` | 右下弹药行/剪影、中央选择提示和名称 |
| `src/weapon_bridge.cpp` | 原生兵装重建、库存/冷却、检查点、输入与声音交接 |
| `su30sm_fixed_mount.hpp`、`mount_expansion.hpp`、`mount_mesh_override.hpp` | 常规布局、逻辑槽到物理位置映射、网格替换与原网格账本 |
| `mount_preview.hpp`、`mount_exterior.hpp`、`light_mount.hpp` | 机库/补给独立预览、机外保留、原生机构及固定效果源 |
| `continuous_sp.hpp`、`raven_sp.hpp` | 已登记 ECM/TLS/UAV 的引用、来源通知、停止、回收和边界清理 |
| `f22_exterior_bones.hpp`、`cfa_muzzle_visual.hpp` | 具名骨/炮口等专项访问；旧方案不因保留代码而自动启用 |
| `mount_animation_*`、`common_bay_animation.hpp` 等控制头 | 原生动画访问、发布及归还基础设施；完整共舱研究不等于现行运行路线 |
| `target_gaze.hpp`、`camera_hold.hpp` | 目标注视与开发候选镜头保持，共享轴读取/手柄观察，分别管理许可与归还 |
| `overlay.cpp`、`ui_messages.hpp`、`keyboard_shortcuts.hpp` | 管理界面、中英提示、快捷键与输入动作队列 |

Lua 表内短文件名均位于 `dist/DualSP/Scripts/`；挂载头文件复用核心私有命名空间中的类型和原生访问函数。修改布局先改源数据并生成核心表和 Lua 资源清单，不能只手改生成结果。

## 许可与事务边界

总开关关闭、多人或模式尚未确认时，核心接管保持关闭。总开关在可见且允许输入的主菜单/单人任务选择等安全入口应用；在任务、补给或机库保存时，等回到安全入口再切换。管理界面只释放自己取得的暂停，不清除原生或其他来源的暂停。

第13关依据原生任务 ID `113` 临时旁路兵装、模型和 HUD 接管，原生任务指定 SP、选装和检查点保持原生；同地图自由飞行 `213` 不命中，第12/14关恢复多SP。离开该关后重新建立会话，不修改个人开关、比例或保存方案，多人限制仍优先。

普通选装/补给读取购买记录；任务调试允许尝试未购买 SP，官方机体列表也标注购买/DLC 状态并允许尝试，不写购买或许可记录。换机先归还管理暂停和旧运行状态，再通过原生 `RestartLevel` 重开完整任务；新受控 Pawn 的类继承、世界、控制器和兵装全部匹配后才确认成功。它不是即时换机，也不承诺检查点换机。调试方案默认尽量三 SP，仍受已登记的功能资格约束，不保存为个人方案。

| 阶段 | 提交与清理规则 |
|---|---|
| 准备页 | SP1、可选 SP2/SP3 独立草稿；真实确认到 STANDBY 后才保存，取消不提交 |
| 补给 | 独立页面/玩家身份；最终 YES/NO 默认 NO，原生起飞成功后才重建并保存 |
| 切换 | 保存各 SP 库存、装填队列和游戏时间，重建后恢复；普通导弹、机炮和干扰弹保留 |
| 检查点 | 独立保存会话与方案；后续补给或调试不能覆盖旧检查点快照 |
| 任务调试 | 重配并补满 SP，保留普通弹药、个人方案及旧检查点；活动武器未结束时可拒绝 |
| 离页/换机/换世界 | 归还自有控件、输入、模型和动画责任，清除旧身份与未消费输入 |

原生循环与直接选择共用最终选择事务，不提交中间 MSL 状态；内部重建和原生回收不重新排队自身请求。原生忽略单次确认/返回边沿时恢复页面、等待新输入，不保存未确认草稿；真正异常仍提示。

后续源码减少事务内重复工作：名称最多240字节、按实际可读内存区分块校验和查找终止符，不缓存页或对象；装填恢复先核对完整原生数组，同栈不调用引擎，集中读取计时并计算全部结果后写回。保留队列旋转、窗口、时长及重建门槛检查。`switch`的临时状态回执保持原子替换和请求编号匹配，但不要求断电持久化；配置、安装等其他文件仍沿原持久化策略。

仅已绑定CFA的切换记录`CFA_SWITCH_COST`，以高精度计数器区分捕获、持续效果保留、模型重建前处理、音效/编号同步、原生Init、效果恢复、装填/类别恢复、模型提交、回执发布九段；单条计时日志在区间结束后写入。原生Init段包含同步钩子成本，不能当作纯引擎自耗时；记录不含Lua写命令、读应答和后续渲染帧。

后续源码的`muzzle_filter`记录各阶段炮口过滤耗时、调用数、命中数及切换前后账本大小。耗时是对应阶段的子集，包含过滤内目标炮口的同步显隐调用，排除直通后的原生显隐；不能和阶段耗时相加，也不是纯查表成本。仅切换时启用计时，嵌套调用只累计最外层时间，异常退出同样结算。

共享目标注视的原生轴入口，按玩家弱身份和当前视角作用域分离环视/注视轴；只覆盖环视返回值，不改原生轴表、相机坐标或整个更新。当前视角输入槽0/1/2分别核对第一人称/座舱/第三人称。松杆保存平滑方向的逆归一化值，补偿50毫秒输入交接；回正让原生向零插值，目标注视优先。特殊判据及座舱委托四元数分支直通。

R3整次按压的原生视角回调均由模组接管；短按释放只回正，确认原生动作且长按满500毫秒才由Lua游戏线程调用一次原生跳板，释放不兼触回正。已有按压使用缓存边沿，无记录时补采硬件，兼容原生动作先到达。释放后的交接也继续隔离：已确认原生动作保留100毫秒，未确认最多等待500毫秒，由Lua调度结束交接，避免重复/迟到回调漏放。XInput只观察R3/L3，原生双摇杆干扰弹不被屏蔽；组合同时回正并取消本次长按。依赖标准R3换视角映射；原生动作没有按键来源，R3及释放交接期间的混合换视角请求也归入该次按压，除此之外继续原生。

暂停、管理、失焦、断连、换代及停用时清旧保持/计时，恢复重采真实按键，不重放旧边沿；500毫秒心跳过期归还。换视角清旧保持并取消未执行动作，当前R3回调隔离保留至松开交接结束。单功能错误只停镜头保持，中英提示保留完整日志，不冻结兵装。原只读研究与实现记录保留；用户反馈镜头保持基本正常，但R3短按同时换视角，后续修订见`evidence/camera-hold-r3-short-press-fix.json`。该源码修订已接收至2.19.2候选，本轮已成套构建、通过现有检查并安装，效果仍待实机验证。

## 数量、配置与视觉隔离

原生武器配置编号是 `0/1/2`，逻辑选择为 MSL/SP1/SP2/SP3；SWP 模型池、Socket 和物理位置是另一个映射。库存、逻辑队列、待发窗口与显示容量不能混为一谈。载量先计原生部件，再按整数百分比向上取整；方案、会话和检查点分别保存比例快照，普通设置保存不补充当前弹药。

兵装事务与外观接管分别成功或失败。外观资格不足时，停止该视觉绑定并逐项归还原生网格、显隐、动画请求；不能把已成功的兵装操作改报失败。归还失败保留旧身份和账本继续恢复，已销毁或序列号变化的对象不再解引用，不声称能强行恢复失效对象。

当前布局范围与取舍统一见[挂载设计](multi-sp-mount-design.md)。优先保留明显机外挂载，内部舱与当前 SP 继续原生；Su-47/TGM 为原生外观旁路，X-02S 不接管外观。CFA 公共机构恢复原生，不以强压开盖进度来实现 ECM 外观隐藏。已发布2.19.0的ADF-01切离TLS（含MSL）立即停止并隐藏主束；后续源码改为先等待自然退场，其他登记TLS/UAV的持续策略分别维护。

FALKEN只读当前玩家的ActiveWeapons和SpawnedWeapons，以TLS类型、玩家归属和活动位判定忙碌，包含已移出活动数组的尾迹；不以结束请求位代替完整退场。机型结论按玩家弱身份缓存，不缓存发射体或反射元数据。旧2.19.1会保存切换请求并等待；当前2.19.2按用户新要求，在释放发射输入前直接拒绝TLS期间的请求并清空等待，结束后必须重新按键，不为该请求轮询或自动重放。普通连射保留原有五秒等待。核心重建及受控类别切换共用门槛，旧停光导出对FALKEN只核对已退场；专用强制End和MainLaser显隐流程已删除。必要的非当前鼻口通道收拢仍沿轻量Parts实现，不能称为完全撤销动画接管；重建成本仍在。

CFA在双/三SP互切时保存公共请求、阶段及进度，并在完整`keepArmed`之后按事务编号恢复一次；MSL边界仍原生开关，半开继续推进。原生更新后仅在选有ADMM时将Body的`swc1`盖板输出同步到公共`spwc`，相同值不写；不强制公共进度、不伪造全开、不在ECM时衰减进度。完整签名在绑定时核对，帧内仅作目标身份及动态范围检查。盖板输出独立记账，重建前/退出时归还，失败保留待恢复状态；兵装成功与外观失败仍分开。2.19.1已安装，用户确认互切不再展开，但仍有明显卡顿，并新增MSL/EML双发反馈。

后续CFA减负源码只在不调用引擎的短只读作用域内共用对象表头，逐项核对地址与序列号；骨显隐维持保留组件/资源身份核对及调用前后的函数弱身份检查，反射布局在绑定或元数据复用时完整核对。不缓存跨帧页面，也不把UObject/Init操作移到后台。`CFA_SWITCH_COST`修订2覆盖模型开关，新增`memory_checks`和`mount_work`重叠子项及目标配置；计时本身有开销，不能与原日志直接等同为纯算法差异。`CFA_WEAPON_SAMPLE`复用HUD采样，记录MSL/EML扣弹、ADMM历史、原生齐射及批次字段，采样间隔扣弹不等于一次按键发射计数。新源码性能尚未验证，见[调查记录](../evidence/cfa44-fire-switch-2.19.1-audit.json)。

CFA发射边界修订基于原生`0x889c90`：每Tick按armed重写`+0x2e4`组号，未消费的单字节按键队列不记录旧类别。`ReleaseWeaponInput`只释放按住状态，不清队列；旧`+0x2c0 && +0x2e0>1`门槛中的`+0x2e0`是计划总数，无法排除活动单发批次。新选择释放输入后调用`dualsp_prepare_cfa_switch`，仅将CFA的`+0x2b8`队列Num清零，保留分配。只读就绪查询、受控类别切换和SP重建共用更完整门槛：活动批次`+0x2c0`、收尾`+0x2c1`、按住输入及未消费队列均为空。忙碌时沿用50ms查询/五秒取消，不占线程等待；已开始批次由原生完成，不改目标数组、弹药或在途效果。机型结论按弱身份缓存，七处代码片段仅首次核对。仅当前玩家会话游戏线程可写Num，诊断不参与状态决策。已修补静态代码证实的跨类别状态漏洞，实机双发是否消失仍待验证，见[原生依据](../evidence/cfa44-admm-fire-transition-fix.json)。

2.19.2现场证实上述批次门槛仍不能消除双发：真正持续污染的是TargetSelectionComponent的LockedTargets（+0x398），不是已清空的按键队列。`0x4c6d10`只清LockonSeekers（+0x468）再建新槽，原先仅调用`0x4c98a0`停音，没有解除旧目标登记；`0x881aa0`复制残留列表，`0x889e80`以列表长度决定本轮发射数量。后续`seeker_rebuild.hpp`在共用初始化及Lua重建准备入口调用`0x4c8ee0`，逐槽经过原生状态0解除登记并停音，再通过原生失效目标过滤及`0x4c7210`解除旧版本遗留的无主登记。保留SelectedTarget、候选表、弹药和正常多重锁定规则，不直接清目标数组Num、不修改发射上限、不加帧钩子。所有经过模组重建的机体共用；纯原生类别切换仍沿原生Reset。源码与[现场证据](../evidence/cfa44-live-seeker-residue.json)对应，新修复未编译安装或实测。

CFA开发修订仅在同机、同激活器/管理器、同池资源的普通切换中保留骨显隐租约，Init后复核并按需补齐；其他重配、退出或失败仍归还。骨架更新开关仍在Init前归还、之后采集原生新值，归还值相同时跳过重复调度。CFA三个固定架不依赖弹药就绪外观，100ms维护跳过ADMM队列复制和位图计算，真实弹药与发射映射不变。显隐请求继续记账，只有目标位改变才调用引擎。

炮口抑制账本按组件地址索引，显隐回调只对命中记录复核弱身份及当前归属；未命中仍按父挂架、Socket、类型和模板审查新炮口。失效地址重新审查，存活组件改挂/换模板时本次请求直通。每次模型提交清理失效记录；活对象保留恢复责任，归还失败仍记录最后原生请求。该修订消除无关请求对历史炮口的全表身份检查，不跳过对象校验、不强行回收粒子或缓存内存页。

多挂CFA的SWP3保持 `bVisible=false`、`bHiddenInGame=true`，并通过原生 `HideBoneByName/PBO_None` 隐藏 `SWPCover_01/04` 两组机构。绑定核对七骨父链和原版网格/骨架，存在持久效果源时核对其 `sp31` 落在未隐藏的 `Body`；不隐藏根骨，不改变ECM持续机制、公共开盖进度或发射阶段。单挂继续原生。组件隐藏不向子组件传播，原生请求保存在恢复账本中。

## 身份、缓存与预览

机库只取当前 `HangarManager.LoadedPlayerPlane`，任务只取实际受控玩家。绑定核对完整类/包、父链、网格、原生池、Socket 双射以及所需 `NoCollision`；资源点数不写回逻辑队列。位置减少或借位时，显示与实际离架共用映射，活动点读取当帧原生世界变换。网格通过引擎 `SetStaticMesh` 替换并登记原值，不直接写网格指针或碰撞设置。

CFA任务外为单独例外：Lua在资源准备和多挂绑定前归还预览并退出，机库、准备、STANDBY等只显示当前原生兵装。核心mode1亦强制原生旁路，不建立CFA多挂池、骨隐藏或模型替换。原生三SP选装与弹药UI仍可用；实际任务玩家mode3、补给mode2/5保持任务内多挂策略，其他机体预览不变。

对象缓存使用地址、UObject 索引和序列号的弱身份；反射元数据还核对类、字段、资源等来源。新实例重新建立归还基线，不能把旧组件的 native/owned 状态继承到新代。纯派生网格资源与 World/Pawn 的生命周期分开管理；保留资源不等于长期保有玩家或场景。

后续源码的`NativeReadBatch`只复用短只读块内刚核验的可读区间，不复用对象字段或身份结论。每次字段读取仍执行memcpy，缓存最多8段且只在局部栈上存活；对象表头、逐项地址/序列号、资源及父链继续核对。反射调用前后使用不同批次，禁止跨ProcessEvent/原生引擎调用、写入、帧或线程持有。仅对象表/布局/骨资源/炮口纯读取路径接入，其他read/write保持即时查页。计时修订3记录实际查页与批次复用量；当前未构建实测，不能宣称已达20ms。

正常换皮肤、页面切换或开场载入导致实例/管理器换代时，先安全归还旧上下文，再等待真实新入口完整重绑，不当成永久结构错误。稳定预览按100ms巡检；失败归还按200ms重试；加载等待不以超时或旧缓存冒充资格成功。同栈网格/显隐回调合并为一次预览维护，原生请求继续记账和转发，批次末复核身份，不无限递归 Apply。

自有派生资源只加载当前组合需要的条目，单挂不预加载其他组合。先查已加载对象，再走已验证的原生精确路径，加载器登记表入口作为后备；仍由核心核对资源身份和原生碰撞。日志分别记录路径/登记表耗时。此优化减少重复工作，不保证消除第一次磁盘/渲染资源冷加载峰。
