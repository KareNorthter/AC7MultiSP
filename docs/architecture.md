# 架构与关键约束

> 当前版本 [0.1.8](version-0.1.8.md) 已由用户初步确认功能可用，沿用候选 7 逻辑。当前核心独立保存在 `dist/DualSP/cores/0.1.8/DualSP.dll`；旧正式核心原值仍受保护。

返回[项目入口](../AGENTS.md)；操作见[使用说明](../AGENTS.md#使用说明)，构建与版本管理见[开发说明](development.md)。

## 模块

| 模块 | 职责 |
|---|---|
| `dist/DualSP/Scripts/main.lua` | 游戏线程调度、机体与世界绑定、原输入观察、配置、补给与检查点事件 |
| `weapon_cycle.lua` | MSL/SP1/SP2 顺序及耗尽跳过 |
| `native_hud.lua` | 固定显示 MSL 和单/双 SP 克隆名称；颜色 Alpha 表示就绪，保护行身份与原生布局 |
| `weapon_names.lua`、`weapon_presentation.lua` | 共用武器简称；中央简称正常显示常驻，不使用通用 RenderOpacity |
| `loadout_flow.lua` | 出击/补给共用双选草稿规则，未确认时不保存 |
| `native_loadout.lua` | 原兵装页与原补给页的独立适配器，复用原生控件与决定/返回映射 |
| `src/weapon_bridge.cpp`、正式 `DualSP.dll` | 捕获、重建、恢复主武器和两套 SP 的独立状态 |
| `src/overlay.cpp`、`DualSPUI.dll` | 管理候选 4 增加准备页只读键盘导航；保留中英文 F8、单键捕获、固定手柄直接选择、按需日志、输入隔离与动作队列 |
| `payload/ue4ss/UE4SS.dll` | 本机 AC7 专用加载器及游戏线程计时接口 |

## 数据与时序

```mermaid
flowchart LR
  A[原生准备与补给页] --> B[按机体保存兵装配置]
  B --> C[main.lua 游戏线程调度]
  C --> D[正式武器核心]
  D --> E[弹药与冷却状态]
  E --> F[原生任务 HUD]
  C --> G[F8 内存界面状态]
  H[F8 管理设置] --> C
```

原生桥接调用仍通过带请求编号的短命令/状态文件交付，状态完整写完后原子替换。任务中不每 100 毫秒执行原生快照；当前弹药读原生公开接口，未激活 SP 在切换、恢复等事务中更新。界面渲染线程读取内存状态，空操作队列不写文件。

玩家机体按所属世界绑定，切换世界时清理缓存。周期更新与延迟输入均在游戏线程执行；不要重新引入旧异步计时器与 Lua 回调注册并发。

武器名称随装填/耗尽状态变为半透明已加入[补给/HUD 合并候选](hud-candidate.md)。每 100 毫秒以只读内存接口采样三组就绪值；固定 SP 行与原生颜色同步保留，不增加周期文件快照。任务开始和补给成功时先接管固定行再初始化武器，避免原生单 SP 短暂露出。正式 0.1.7 核心不包含新接口，不能与候选 Lua 混装。

合并候选 3 加入逻辑选择事务，管理版保留该机制并移除 F9：SP 重建和原生按下/释放结束后，统一提交右下选择箭头及中央简称；事务中保持上一项显示。右下箭头使用独立克隆，原箭头保留在折叠 Canvas 中接受游戏写入；关闭及重置时恢复。避免原生先经过 MSL 时覆盖可见选择，不改核心切换协议。

中央武器提示按用户最新要求显示“当前武器简称正常亮度常驻”。独立原生文字控件复用原提示样式和位置，原瞬时面板保留在折叠容器中；依据最终的 MSL/SP1/SP2 选择复用右下角简称文本，不设置计时或淡化，整体服从全局 HUD 显隐。实现边界见[合并候选](hud-candidate.md)，前期依据见[评估](research/persistent-weapon-message.md)。

## 兵装重建

`InitializeWeaponSystem` 会重建武器系统，不能视为普通切换。核心保存主导弹、机炮/干扰弹计数和两组 SP 的独立值、装填队列及捕获时间，切换后映射到新槽位，使用游戏时间推进冷却。不能复制旧武器实例指针。

物理槽与逻辑 SP1/SP2 不是同一概念；模型、挂点和发射实例仍受单个活动 SP 配置管理。因此状态缓存正常并不意味着已实现双模型，详见[核心研究](research/core-findings.md)和[模型研究](research/weapon-models.md)。

## 管理与直接选择源码

[管理版源码](mod-management.md)移除 F9 和 F8 兵装编辑事务，原生双选为唯一兵装入口。界面只提交功能参数或任务内直接选择目标；渲染线程不访问 UE 对象，游戏线程验证设置和任务操作条件。键盘按下及手柄固定三方向共用 `selectLogicalWeapon`，不通过模拟多次循环来定位目标。

中央与右下 HUD 使用独立开关和错误状态；右下采样失败不会停用中央文字。中央关闭时由已有模块完整还原原生瞬时面板。管理设置使用请求编号确认，写盘成功才替换运行配置；配弹比例只进入下一次新开的原生草稿，不修改当前任务或检查点。日志页只按需读取模组日志末尾。

新版 UI 导出管理协议标记，控制器加载时必须找到该标记；界面也必须收到控制器的管理协议。安装工具新增 `--management` 模式并核对导出，旧模式禁止管理源码混装。管理候选 1 已于 2026-10-13 14:30 构建新版 UI 并统一安装，武器核心沿用既有候选；真实游戏行为仍待用户验证。

## 保护边界

正式核心 DLL 来自用户实测组合，新编译候选不得覆盖它。其 hash 与当前其余运行文件记录在[基线说明](../Release/baseline-0.1.7.json)。F8 和原生 UI 接入失败不应冻结已经正常运行的武器核心，但必须记录明确错误。

准备页的选择先暂存；管理候选 4 通过真实原生决定及旧页关闭确认后，调用 `NimbusGameInstance:SetPlaneAndSWP` 对齐 SP1 并保存双选。共享 API 的预览/悬停写入不等于用户确认；交接后不能重新启用已退出的菜单。详情见[原生选择页](native-loadout.md)。

## AC8 补给界面调整

管理候选 2 在原生视频/类型区域增加两个空 Canvas 信息栏，仅克隆文字和图片叶模板，不复制 UserWidget 子树或 Slots。原单栏及视频折叠保留，Canvas 自动尺寸属性随源槽恢复。两栏独立展示草稿预览，SP2 不兼容时明确待重选；不根据截图数字改变武器核心。

补给最终页由真实输入控制 YES/NO：NO 从 SP1 重选，返回回 SP2；候选 5 的 YES 等待决定键释放，暂存事务并恢复原生视觉树，再通过独立核心桥接调用原生页面的实际 YES 入口。候选 5 的控件禁用无法阻止此页面输入；候选 6 改为在补给开始时绑定玩家并隔离两个原生输入入口。原生 YES 自行完成武器收尾、关闭菜单栈及任务通知。`OnFinishdSupplyMenuHandler` 只观察，不再主动调用。页面隐藏期间保留事务，等任务补给成功及玩家可用后才应用与保存。修订依据见[原生流程复核](native-flow-revision.md)。

## 准备确认、双栏与重进

管理候选 4 根据授权实机诊断修正三个接入假设。游戏运行时为文字插入 Overlay/HorizontalBox，布局保存恢复统一支持三种槽；新增文字从干净对象初始化字体和样式，避免复制原生隐藏动画状态。高亮坐标读取可见祖先 Canvas。键盘导航通过 UI DLL 的只读 `dualsp_preparation_navigation` 读取前台 AC7 的上下/W/S；决定、返回和手柄仍由页面所属控制器读取，不发送或拦截游戏按键。

实机原生 C++ 确认没有经过共享 setter 的 Lua 反射钩子。准备提交以“已明确交接、真实决定输入、同机体/世界、旧页关闭或停止控制”为依据，再写入并核对原生 SP1、保存双 SP；共享 setter 钩子只保护参数，不承担保存。取消、修改、进入确认页或打开 F8 均不提交。补给继续使用独立结束/成功事件，没有改用准备页关闭协议。实机范围见[准备验证](../evidence/preparation-live-validation.json)。

管理候选 3 将出击确认页纳入草稿导航：可编辑 SP1/SP2，返回回 SP2；明确选择继续后才等待按键释放并交还原生输入。SP1 返回进入取消交接，保留信息显示到原生离开；未确认草稿不进入保存事务。取消后的共享原生写入保护进入页面时的原生 SP1，不能阻止游戏本身的决定跳转。

原生 `MenuBaseWidget:SetIsEnableControl` 钩子和可见性观察负责清理、重新接入；自己的输入禁用带调用深度标记，不误判重进。实机证实内部 C++ 路径不必经过反射钩子，因此以可见性和真实决定共同确认准备提交。接入错误不会因一般激活而重试。补给事件路径仍待实玩验证。

两页共用叶控件双栏构建和草稿呈现，分别计算原生布局。准备栏挂 `WeaponInformation` 根 Canvas，原性能包装组件折叠；高亮挂可见列表克隆父级。SP1 改动冲突的 SP2 标为待重选，普通弹药格保持一致。尺寸、退出步骤和边界见[原生选择页](native-loadout.md)。

## 中途补给源码候选

补给由任务开始事件建立事务，由实际菜单阶段接入 `MissionResupplyWidget`；SP1/SP2 确认后暂存，只有收到补给成功事件且原任务玩家武器恢复可用时才重建和保存。补给事务期间暂停切换和 HUD 弹药读取，F8 不能绕过原生双选提交。取消与任务退出不保存草稿，错误明确停用武器修改。交互及未验证事件时序见[原生补给说明](native-resupply.md)。

核心源码新增 `resupply_setup`，与普通 `setup` 的区别是保留之前的检查点。Lua 的检查点配置与核心快照同步；补给更换兵装后不能用新配置恢复旧快照。正式 DLL 保持原 hash；支持新协议的独立候选已于 2026-10-13 构建并安装到游戏副本，当前对应 Lua 也已安装。正式载荷仍为 0.1.7，不能直接同步候选源码。

候选 5 的 Lua 类别切换与核心 `keepArmed` 均使用完整 `PlayerPlane` 按下/释放流程。该流程在切换激活器后重绑锁定组件，应用原生部件修正；原先直接 `ToggleSpecial` 会漏掉这一步，已被替换。重建前的 `ReleaseWeaponInput` 只负责发射输入收尾，不再声称它能清除 seeker 音效。最终武器类别核对成功后才刷新 HUD；没有按周期重建或写死武器射程。

## 候选 6 的输入与音效边界

补给输入隔离覆盖原生 YES/NO 与单 SP 列表的两个处理函数，仅匹配本轮飞机、激活器和页面；页面 Tick、动画、其他菜单与全局按键缓存不改。成功应用、检查点恢复或离开任务后解除身份绑定。错误继续明确报告，不能将未确认草稿保存为成功。

锁定音的播放标记属于旧锁定槽，初始化会替换这些槽。所有模组兵装重建必须先调用原生逐槽停止音效，再检查组件引用归零，最后执行原生初始化与锁定参数同步。不能在新槽生成后补清计数。源码状态与证据见[候选 6](input-audio-revision.md)。

## 候选 7 的补给阶段身份

本机加载器的 Actor.GetWorld 返回 Outer 链中的 World；返航阶段可能位于流式子关卡，不能与 GameInstance 的运行任务 World 直接比较。菜单开始时保存阶段实例与自身关卡 World，结束时严格匹配二者，并独立检查 GameInstance 的任务 World。撤回结束时重新绑定阶段的做法。结束后回调标记完成，任务成功与玩家可用后才提交和恢复双 SP；不靠吞掉断言继续执行。候选 6 用户已确认本次音效未再出现、双选及起飞正常；候选 7 尚待实玩，依据见[修订](resupply-completion-revision.md)。
