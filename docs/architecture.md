# 架构与关键约束

对应 1.1.0 功能基线。验证范围见[当前状态](status.md)，构建入口见[开发说明](development.md)。

## 数据与线程

原生选装草稿 → 原生确认交接 → 机体方案 → 游戏线程核心会话 → HUD。
管理渲染线程只读内存状态并提交动作，不能直接操作引擎对象；设置、直接选择和调试请求由游戏线程校验。

逻辑选择 0/1/2/3 表示 MSL/SP1/SP2/SP3；机体原生配置编号为 0/1/2，不能混用。
方案 a/b/c 连续占槽，空槽为 -1，不允许重复；实际搭载数决定均分。名称来自原生表，运行行为按实际武器类判断。

配置 schema=2，管理参数版本与协议均为 3。UI 状态自身的 schema=1 不等于个人配置版本，不能据此降级配置。
短事务使用请求编号和命令/回执；常规 HUD 通过就绪接口采样，不周期写完整武器快照。

## 生命周期

- **出击**：依次确认 SP1、可选 SP2/SP3；选择空槽结束后续选择。交还真实原生动作进入 STANDBY，未完成确认不保存。
- **补给**：绑定本页与玩家身份，隔离原生单 SP 输入；多选之后进入 YES/NO，默认 NO。YES 经真实原生起飞链，成功后才重建、保存和交接 HUD，不主动伪造完成事件。
- **普通切换**：捕获独立弹药/装填队列与游戏时间，重建目标 SP 后恢复；保留普通弹药、机炮和干扰弹。原生类别切换、最终 HUD 与音效统一提交。
- **固定挂载**：逻辑槽和物理模型分开；显示与发射使用同一映射。重建前解绑，按新对象身份重绑；活动挂点读取实时世界变换。
- **检查点**：独立保存会话及方案；补给或调试不能覆盖旧检查点。恢复旧检查点不得套用后来补给的方案。
- **调试换装**：显式应用后重配并补满 SP，选回 MSL；保留普通弹药、原检查点及个人方案。未来合法新检查点可以记录调试方案。
- **暂停**：F6 只释放自己取得的暂停；已有原生暂停保留。交接失败显示错误，不能强制写零。
- **离页/换世界**：只归还本模块拥有的控件与输入，释放事务和对象缓存；STANDBY/PART 不接管整个页面根节点。

## 身份与失败处理

机库使用实际 LoadedPlayerPlane，任务使用实际玩家；核对类继承链、世界、组件及模型池，不能通过猜测名称寻找替代对象。
固定挂载还用对象索引和序列号识别实例，防止地址复用。每次进程/任务重新采样，旧地址不是长期常量。

共享菜单的 UIGameMode 也继承 LobbyGameMode/MultiPlayerGameMode；不能仅据父类判多人。先核对联网状态与已知菜单，再识别多人页面。
模式变化清理旧事务；Lua、核心和 UI 都服从单人许可。

正常模型切换使用等待/占位，10 秒超时明确失败；不隐藏整页或伪造数据。未知机型按未适配规则使用原生当前 SP 模型；已匹配机型身份异常必须报错。
错误恢复需要归还自有状态并保留日志，不能把异常吞掉后标记接入成功。

## 当前能力边界

固定挂载仅原版 Su-30SM/F-35C/F-15E，详细规则按需读[挂载指南](mount-guide.md)。机库/演出实例另有生命周期。
UAV/ECM 保留单挂限制；TLS 跨 SP 收尾，TLS→MSL 与固定炮体显示分别处理。
中央简称保留开关，右下 HUD 和直接选择固定启用；未就绪变淡，服从原生全局显隐。
