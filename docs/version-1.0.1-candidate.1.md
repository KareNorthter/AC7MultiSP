## 多人禁用

- 首次安装后用户反馈全部功能失效，启动日志为 disabled multiplayer_mode。已修正误把共享 LobbyGameMode 当作多人专用类型的问题：单人机库也使用该类型，菜单必须按实际页面区分；网络状态与 MultiPlayerGameMode 的禁用保留。模式切换日志增加世界和模式类名，便于核实识别依据。修正后的实际启动结果仍待确认。
- 上一条首次修正仍失败。英文启动日志显示 AceUIGameMode_C 被多人基类判断命中；现场只读核实其继承链为 UIGameMode → LobbyGameMode → MultiPlayerGameMode。当前改为先识别已知菜单地图中的 UIGameMode，再依据菜单页面区分单人/多人，其他多人类型及联网世界仍禁止。不是删除多人保护，也不由游戏语言决定启用状态。
- 09:42 再次安装并按用户要求重启游戏，日志确认 enabled singleplayer_menu、GAME_TEXT_CULTURE en 和 CATALOGUE_READY，管理状态持续发布且无 error。此次已验证启动许可和英文识别，F8 实际按键、多人及任务仍由用户复测。现场继承链与结果见[菜单继承记录](../evidence/1.0.1-candidate1-menu-inheritance.json)。
- 新增只读 runtime_context.lua：使用原生 IsStandalone、GameMode 类型及当前菜单管理器中的页面识别多人。菜单中的多人入口尚未连网也禁用；通用对话框或选项页保持禁用，只有明确返回主菜单/单人入口才恢复。
- 多人机库的多个类继承 CommonHangar 系列，而非 MultiMenuBaseWidget，逐项纳入识别。类型分类缓存，不增加周期全局对象扫描。
- Lua 在调度、修改型事件及延迟切换前核对许可；模式变化丢弃旧请求，清除单人任务/检查点缓存，不改已保存方案。
- 核心与 UI 新增独立的 dualsp_runtime_gate，默认关闭。禁用时原生钩子直通，接口拒绝修改，释放音效/输入身份；F8、Back + Y、直接选择和管理导航均不接管按键，也不绘制管理界面或暂停游戏。
- 未知/过渡世界不启用功能。识别或清理错误写入 RUNTIME_CONTEXT_ERROR，关闭两个许可并逐项释放自定义界面，清理错误单独记录；停用到重启，不以旧单人许可继续运行。

这是功能禁用，不是卸载加载器或撤销所有已安装钩子，不能据此保证联网或反作弊兼容。实际多人大厅、房主/客户端、断线及返回单人的覆盖等待用户验证。

## 英文体验

准备、补给的操作提示、空槽及未购买提示跟随游戏文本语言；通过原生 LocalizationManager:GetCulture 获取，不使用配音或系统语言。原生武器说明仍由游戏本地化。中英文以外的语言使用英文模组提示。

F8 新增“跟随游戏 / Game language”，新配置默认跟随。旧配置的 zh/en 手动选择保留，不擅自覆盖；旧用户在 F8 选择 Game language 或 English 后保存即可。F8 语言与原生页面语言可以独立设置。诊断日志和底层错误保留原文，管理界面提供对应语言的错误提示。

英文武器说明中的单换行转换为空格，不再将相邻单词拼接；段落保留。准备页既有英文名称和三行布局保留，不改变兵装或配弹算法。英文版页面的实际溢出、字体和输入表现尚未进行视觉验收。

## 补给后 HUD

用户此前反馈：补给起飞后恢复任务画面，短暂显示 MSL＋单个 SP，随后才恢复双 SP。源码发现两个时序缺口：补给期间移除模组行；configureFlight 在补给事务仍存在时调用 refreshHUD，后者又将刚预建的行恢复为原生显示。

本候选在补给开始时保留右下控件，由原生 HUD 祖先控制过场显隐；完成 YES 交接后读取草稿副本，起飞过场即可预建正确名称，弹药暂显示占位符。只有任务成功和玩家可用后才应用武器与保存。初始化完成标记 applied，使事务收尾不会撤销 HUD，并在同一回调内刷新真实数据。

菜单关闭可能发生在结束交接回调内部，因此关闭事件只记录状态，草稿预览在结束回调返回后建立，不依赖两事件的先后顺序。

单 SP 与双 SP 之间换装会在同帧还原尺寸并重排行，不延用错误高度。不提前提交补给，不改原生起飞流程。上述是代码层修订依据，不能宣称已完全消除实机闪现。
