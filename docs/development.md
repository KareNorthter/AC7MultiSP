## 正式交付与再次打包

2.16运行文件与`evidence/2.16.0-installed.json`逐项一致。发布沿用同一核心、UI、14份Lua及模型PAK，不把dist中的旧DLL当成当前核心。正式包另有音频、专用加载器、许可证、脱敏安装回执和离线运行库，不含个人配置/存档/日志/其他Mod。

本轮发布入口为`src/release_package.py`，从冻结构建核对源码快照、安装与已有测试回执，旧1.1包完整校验后仅恢复微软运行库，并核签名、逐成员回读。其前身`src/package-release.py`仍为历史构建快照的一部分，保字节但不用于当前发布。

发布包路径`Release/AC7MultiSP-2.16.0.zip`，回执`evidence/2.16.0-release.json`。同名文件不覆盖；未来版本先明确版本和来源，再更新打包器的版本准入。

```powershell
python -X utf8 src/release_package.py --build-dir Temp/build-2.16.0-final
```

上述命令仅在没有同名交付时使用；不会构建或启动游戏。文档和新打包器独立于已测产品来源。`src/product.json`的candidate=true保留构建时原字节，发布回执Candidate=false与Git正式标签表达当前正式状态；不为改元数据重编译。

## 后续开发流程

1. 看Git状态，从main新建`codex/`分支；不继续修改封存研究工作树。
2. 更改唯一源码及对应正文。布局调整同时维护源JSON、生成表和资源配方；不只改生成结果。
3. 用户明确授权后，才完整构建并运行适用检查。新构建使用独立Temp目录，不能覆盖旧实测产物。
4. 安装基线显式指向2.16-installed；保留个人配置、存档与其他Mod，游戏正常退出后才交换文件。
5. 用户测试确认范围后合入main；发布沿用该已测字节，记录仍待解决的问题。不要自动推送或上传。

构建/检查/安装入口分别为`src/build.py`、`tests/run.py`、`src/install.py`。当前2.16冻结来源包括旧工具和11份证据，内容/路径变动会使来源校验拒绝；不能把这种拒绝简单改成通过。未来开发要在新构建里完整冻结新来源。
