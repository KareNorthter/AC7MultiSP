# 有价值的方案决策

返回[项目入口](../../AGENTS.md)。本页替代冗长的早期版本流水账；原理见[核心研究](research/core-findings.md)，证据目录见[索引](../../evidence/README.md)。

| 问题 | 当前决定及原因 |
|---|---|
| 切换会补弹、重置冷却 | 重建前捕获独立状态，重建后映射装填队列；直接调用初始化接口无法满足需求 |
| 游戏运行后崩溃 | 旧栈出现 Lua 错误与回调注册链，不能断言武器重建是根因；周期和延迟调度统一到游戏线程，并保留明确错误 |
| F8 光标闪烁、回中 | 仅面板打开时管理自己的指针及相关输入限制，关闭时恢复；用户已确认光标问题修复 |
| 弹药耗尽后无法切换 | 切换逻辑使用即时计数，跳过耗尽 SP；不能继续展示停止同步前的缓存为实时值 |
| 独立任务 HUD 不融合 | 改用原生 UMG 列表，保留游戏字体、颜色、锚点和缩放 |
| 2K 下文字重叠 | 不按屏幕像素或箭头间距定位文字；使用真实原生列顺序与文字期望高度 |
| 切换时两行短暂互换 | SP1/SP2 显示控件固定身份，不再重排行身份；原生当前 SP 文本与可见两行分开 |
| 周期明显卡顿疑虑 | 去掉任务中的重复原生快照和全局扫描，内存交付 F8 状态；没有帧时间实测，不能宣称已确认旧模组为卡顿根因 |
| 原生准备页只有单 SP 流程 | 在原兵装页分阶段暂存双选，SP1/SP2 各确认一次后直接交接 STANDBY；旧版额外确认步骤已撤销，用户实测通过 |
| 中途补给需要重新双选 | 复用 `MissionResupply` 自身的列表、光标和信息栏；光标副本移入对应行 Canvas，起飞入口等待按键释放后调用，结束阶段保留事务，只有补给成功时才清理、重建并保存 |
| 返航换装会丢失旧检查点 | 候选核心新增保留检查点的补给重建命令，Lua 同步保存检查点配置；正式 DLL 不覆盖，也不允许新 Lua 与旧协议混装 |
| 用户实玩出击选择在初始化时停止 | AC7 当前 Widget 没有通用 RenderOpacity；Image 也缺少新版本画刷 tint setter。出击/补给共用折叠源容器，HUD 使用克隆文字及颜色 Alpha；历史模拟与较新引擎文档不作为当前接口存在性的证明 |
| 出击页仍在槽识别处停止 | 读取实际槽的原生类全名并记录来源，只接入资源已核对的 Canvas/Horizontal；旧日志没有实际类，不能断言活跃槽不受支持或 IsA 自身有错 |
| SP1 → SP2 短暂闪 MSL | 原生类别切换与 SP 重建作为一次选择事务提交，右下箭头克隆隔离原生中间态；中央和箭头共用最终选择，保留原生切换输入及冷却规则 |
| F8 是否继续选兵装 | 用户最新要求只管理功能、参数、键位和日志；源码删除第二套兵装交互及 F9，原生页面是唯一选择入口，失败明确报告 |
| 直接选择与两处 HUD 如何同步 | 键盘及固定手柄提交明确目标，复用一次逻辑选择事务；不连续模拟循环键，不重建当前已选目标 |
| 中央常驻提示如何关闭 | 完整还原游戏原瞬时提示面板，由原生计时控制；中央开关及错误独立于右下列表 |
| 双模型会在切换时瞬变 | 单纯叠加挂架会重叠且不解决发射来源；保留后续目标，暂不安装装饰性模型方案 |

旧版本二进制、重复包、失败测试临时文件已不作为开发依据；关键失败机制与尚未确认的边界仍在本页、研究文档及精选证据中保留。
