二、已完成的功能源码

1. 中央武器简称更清晰
   从主工作区按实际差异移植四行修改：正常 Alpha 0.5→0.7，字号比例 10/9→11/9，通常 20→22。
   装填/耗尽仍乘 35%，最终 Alpha 0.245；绿色、局部泛光、位置、HUD 显隐和现有独立开关不变。
   上移至画面高度 30%、同色方框与固定开启仍保留在 ui-optimization-plan.txt，暂不实现。

2. STANDBY/PART 三个 SP 卡片向右移
   三个纵向卡片共同右移 32 个逻辑像素，卡片宽度、字体和条长不变。
   新 cardX 与原生 origin 分开，左侧弹药块仍使用未平移的原生定位基准，避免跟着偏移。
   保留 .5 的 PART 弹药下移 100 和 SP2/SP3 默认首个可选项，也保留 .4 的 Overlay 包装层修复。
   选装横向三列和补给框位置不受本次右移影响。

3. PART 悬停弹药预览与黄色数字
   核心新接口只复制当前页面 HangarStatus 的弹药上下文，通过已核对的原生函数计算，
   不调用原生绘制入口，不安装/卸载部件，不写 GameInstance、方案或任务弹药。
   当前上下文列表构成 A；原生模式允许且候选未在该列表中时构成 B；每个真实 WeaponID 分别计算。
   Lua 最后复用 Profile.ammo，按当前实际搭载的 1/2/3 个 SP 均分，EMPTY 不参与。
   受候选影响的 SP 数字使用 TextColorOnCursor、TextGlowOnCursor，关闭全局泛光继承；
   不受影响时恢复 TextColorStandard 与全局泛光。名称不染黄，不添加闪烁。
   沿用原生影响标记：即使均分取整后显示整数不变，适用候选仍可以变黄。
   MSL/GUN/FLR 继续由原生更新，模组不新增第二套数量/颜色写入。

   每约 50 ms 查询当前绑定页面的候选；已装选项仍按原有 250 ms 规则刷新。
   两类刷新统一走 paintColumns，候选保存在 c.partsPreview，绝不覆盖 flow.options.max。
   数量/影响标记与静态名称/性能分开判断，候选移动不会反复重画 18 个未变化的基础性能条。

   页面与上下文机体尚未同步时，只把模组 SP 数字显示为 ---，记录 PARTS_AMMO_WAIT；
   同步后记录 PARTS_AMMO_READY，超过 3 秒明确报错。该等待不阻止原生 PART 导航。
   对象归属、访问器、函数签名或结果异常走已有明确错误路径，不拿旧数量静默替代。

三、弹药接入的证据与尚未实测边界

原始证据：parts-ammo-hover-preview.txt、evidence/parts-ammo-hover-research.json。
本次继续只读分析此前已保存的运行时指令和对象索引，没有采集用户当前测试现场。

已核对的结构/入口：
• CampaignHangarPartsWidget.HangarStatus 位于页面 +0x4f8；弹药控制器 Parent 为 +0x28。
• 控制器虚表 +0x258 为 0x8df100，转发到 HangarStatus；后者相同槽为 0x8df120，返回 status+0x4c。
• 上下文复制 0x34 字节：机体、原生 SP、保留字段、候选、八个部件 ID、有效数量。
• 0x6ec5c0 在控制器 +0x58==2 时构造绘制模式 3，否则 2。
  查询使用这条已核对规则，不依赖可能未刷新的 +0x50，也不强制所有 PART 状态都有候选预览。
• 0x6f01c7～0x6f0206：遍历上下文列表构建 A，候选不在列表且模式为 3 时构建 B。
• 0x84e770 按单个 PartsID 累计修正；0x84dc40 逐 WeaponID 计算并返回候选影响标记。
  新接口对两次数量均从基础载量开始，避免重复应用已装增益。
• 旧对象快照可见 TextColorStandard/TextColorOnCursor/TextGlowOnCursor。
  没有 TextGlowStandard；标准状态依照原生恢复全局泛光，不读取虚构字段。

用原生上下文列表与原生模式处理替换/卸件，而不是自行推导“A 加某个新部件”。
但是本批没有执行满槽、冲突、卸件、已装重悬停或普通导弹黄字实机对照，不能宣称这些边界已通过。
此前 SP.W Lv.1 的只读现场是在模组启用时取得，也不能替代关闭模组后的原生 A/B。
旧核心没有新查询导出，Lua 启动时会明确拒绝，不支持混装后继续运行。

四、性能处理与仍待定位的卡顿

已做的有限优化：
• 原生激活事件给出的页面保留到适配器候选缓存，不在随后首次轮询立即再全局发现一次。
• 等待模型时沿用已绑定且由 pump 检查过世界/机体/可见性的 owner，不每 500 ms 再扫同类页面。
• optionsFor 菜单分支不再对同一个预览实例重复遍历一次类继承链，任务实例仍独立校验。
• PART 数量/颜色变化不触发静态名称和基础性能条重绘。

新增一次接入一条记录：
  NATIVE_UI_ATTACH_COST mode=... plane=... options_ms=... build_ms=...
分别表示最后一次选项查询、页面创建及首轮同步绘制的 Lua 时钟耗时。
NATIVE_MODEL_READY 补充 lua_clock_wait_ms；保留 NATIVE_MODEL_WAIT 与原有 10 秒超时。
这些沿用既有 os.clock，不是 GPU 呈现时间，不涵盖全部激活钩子/原生加载成本。
日志按接入和状态变化输出，不逐控件、逐帧落盘。

没有本次卡顿现场帧时间，不能将上述改动称为“卡顿已修复”。
下一批先对照模型等待与 build_ms；若后者仍高，再考虑可取消的分帧隐藏构建。
当前不拆分显示、不取消身份检查、不延长超时掩盖失败，也不减少错误报告。

六、建议下一批一次性验证

以下由集成方构建安装后，配合用户正常游玩完成；本文件不要求现在打断游戏。

1. STANDBY/PART 位置：中文/英文至少当前使用语言，三实槽与 EMPTY 各一次。
   三 SP 比机体栏更疏朗、右缘不裁切；PART 弹药仍避开容量条，退出再进不累计偏移。
2. PART 基础预览：先悬停未装 SP.W Lv.1，再移到无关部件，观察适用 SP 的数量和黄字来回切换。
   分别用单/双/三挂确认先计部件再均分；MSL 增弹部件只影响应影响的数量。
3. PART 边界：已装部件重悬停、同组替换、卸件、满容量/不可安装、快速切页签和换机。
   无重复加成、无旧候选残留，确认前实际方案不变；允许原生不提供预览的模式保持当前显示。
4. 出击与补给：默认 SP2/SP3 光标保持 .5 已验证行为，补给确认/取消仍正常；不把 PART 黄色带入飞行。
5. HUD：MSL 和各 SP 正常/装填/耗尽时均清楚，字号略大但无裁切，颜色与过场显隐正确。
   位置不动、没有框；现有独立开关行为保持，旧关闭配置本批不强制迁移。
6. 选机停顿：冷热换机各记录几次，若出现明显一顿，保留同轮 MODEL_WAIT/READY、UI_ATTACH_COST、PERF_TICK。
   根据分段记录再定进一步优化，不把没有遇到卡顿等同于所有机型已解决。
7. 集成回归：.7 Su-30SM、F-35C、F-15E 挂载以及 TLS→MSL 的既有范围保持；本批没有更改相关源文件。
