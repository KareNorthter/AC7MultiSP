## 使用流程

1. 选择机体，进入原特殊兵装页。上下方向键、W/S、手柄十字键或左摇杆导航，原生决定键选择 SP1。键盘 W/S 已实机验证。
2. 选择 SP2。列表排除 SP1，最后提供“无兵装”；不能双挂的 UAV/ECM 组合只提供空 SP2。返回键回 SP1。
3. 确认页可分别“修改 SP1”“修改 SP2”；返回键回 SP2。双栏同时显示名称、六项性能、类型和预计弹药。这时仍是草稿，不保存。
4. 选择“交给原生菜单继续”，松开按键，再按一次原生决定键进入待命页。真实决定后原生旧页关闭或停止控制，才写入并核对原生 SP1，再保存双 SP 配置。待命页的 SORTIE 仍由游戏负责出击。

SP1 页返回会取消草稿；松开后再按原生返回键真正离开。取消不保存，重进从已保存方案开始。改变机体/世界、打开 F8 或只进入确认页不提交。交接后误按原生决定的取消路径未单独实测。

## 加载失败的根因与修复

- 游戏启动后将文字包入 Overlay/HorizontalBox，实际槽与离线 Canvas 资源不同。现在统一保存和还原 Canvas、HorizontalBox、Overlay；保留源控件的对象身份和原槽格式，高亮从可见祖先 Canvas 定位。
- 原生文字模板带隐藏动画内部状态，整对象克隆仍不显示。新增文字从干净对象初始化，只复制已核对的字体和显示样式；图片同样独立初始化。
- 原生页面禁止控制时，UE 控制器没有返回 W/S 导航状态。UI DLL 提供只读 `dualsp_preparation_navigation`，只读取前台 AC7 的上下/W/S，F8 打开时不导航；不模拟或拦截按键。决定、返回及手柄仍读页面所属控制器和实际游戏映射。
- 原生 C++ 确认没有经过共享 setter 的反射钩子。保存现在明确要求已交接、真实决定、同机体/世界与旧页关闭，随后核对 SP1。共享 setter 钩子只保护参数，补给仍使用自己的结束/成功事件。

这些结论来自本轮运行日志与截图，历史接口/槽错误见[接口诊断](../../evidence/native-ui-api-failure.json)、[槽诊断](../../evidence/native-ui-slot-switch-findings.json)和[准备复核](../../evidence/preparation-review-findings.json)。音效研究保留，未实现。
