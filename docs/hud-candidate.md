## 实现与边界

`weapon_names.lua` 统一兵装简称；`weapon_presentation.lua` 在原生飞行 HUD 中创建一条常驻文字，原瞬时武器提示保留在折叠的独立父容器下，避免重复显示及与原生隐藏计时争夺同一控件。关闭或重置时恢复原面板位置并移除本模块控件。候选 2 的 `native_hud.lua` 统一管理 MSL 和单/双 SP 名称，通过独立克隆避免游戏颜色更新覆盖就绪状态，固定行身份不变。

核心新增只读 `dualsp_hud_readiness`，根据弹药、逻辑队列、装填窗口和各槽计时返回三组就绪布尔值。MSL 和活动 SP 来自实时捕获，未激活 SP 依据核心缓存和游戏时间推进。切换后使用真实的新实例计时；现有核心的重建阈值处理仍保持不变。多联、持续发射及其他特殊兵装仍需逐类实玩，不能把通用计时判断写成全部武器实测通过。

周期采样通过 Lua 栈直接交付，不创建命令/状态文件。AC7 专用 UE4SS 没有直接导出 `lua_*`，因此从具名 LuaMadeSimple 导出的已核对转发中取得 Lua C API；不构造跨编译器 C++ 对象。安装时离线核对五个导出前缀及可执行代码区目标，运行时再次核对前缀和目标范围。此接口只适用于本机专用加载器，不支持换用任意 UE4SS。

采样与 UI 操作都在游戏线程，复用约 100 毫秒周期。正常飞行不重复扫描控件树，不创建额外渲染层；简称和透明度只在对应状态变化时写入。任务开始和补给成功时做一次 HUD 预热，先固定双 SP 行再初始化武器；等待 HUD 实例生成时只在接管前以约 50 毫秒间隔短扫描，并先折叠原生 SP 行，避免原生单 SP 闪现。接管后仍按周期刷新真实就绪状态，用户尚未复测本轮修复。

HUD 接入或采样失败会记录日志，并通过既有 F8 的 HUD 错误字段显示原因；恢复原提示并停用新 HUD，不把原显示冒充新功能成功，也不冻结已正常工作的武器核心。

## 用户实玩重点

优先确认原生出击选择能进入 SP1/SP2/确认页，再检查原游戏键及 F9 的 SP1 → SP2 是否仍短暂显示 MSL。若加载失败，日志应包含实际槽类型与来源。随后核对 MSL 发射一枚而另一枚可用时仍正常，全部可用弹发射后变淡，第一枚装填完成即恢复；再核对两个 SP 各自冷却和零弹药显示。中央文字应随 **MSL → SP1 → SP2 → MSL** 更新且一直保持正常显示，不能出现长说明、重复提示或闪烁。

随后核对单 SP、原生键、连续快速切换、F8/暂停、HUD 开关、过场、补给重选、连续返航、检查点和任务退出。类别/槽位重建现在会在核心换槽后再次释放激活器输入，并改用激活器的原生 `ToggleSpecial` 入口，目标是停止旧 MSL seeker 循环；这仍需用户实测确认。记录异常时的机体、兵装、任务及日志。候选未运行测试模块，代理不启动或游玩 AC7。
