## 需求理解

按用户最新要求，中央提示始终完整显示当前武器简称，与右下角武器名称使用相同文本，例如 `MSL`、`HVAA`、`UGB`。切换完成后直接更新为新武器简称，不自动消失、不随时间变淡，也不显示完整武器说明、弹药数字或其他前后缀。只保留当前一条信息，不积累历史提示。

在正常任务 HUD 显示且当前武器已确定时，即可显示，无需等第一次切换。关闭 HUD、进入菜单、补给、过场或退出任务时，仍应跟随游戏隐藏。

保持正常显示亮度，取消停留时长、渐变及常驻透明度参数。这里的完整显示指不叠加额外淡化，也不破坏游戏整体 HUD 显隐和原生颜色样式。保持原有位置，不擅自移到准星中心。

## 结论

可行，预计与当前右下角双 SP HUD 及拟议的装填提示兼容。新要求只涉及当前选择、简称文本和常驻显示，比之前带计时淡化的方案更简单。若采用独立控制的原生 UMG 提示，预计主要修改 Lua，不需要修改武器重建和冷却核心；原生隐藏入口尚未定位，仍需明确接管显示流程。

本轮仅完成自有游戏资源的离线结构核对，没有实现、编译、运行测试或启动游戏，也没有测量帧率。

## 本机结构依据

对 Steam build 9855922 的补丁包和基础包分别解析后确认：

- `AceMainFlightHUD` 中存在 `WeaponMessagePanel`，它的子控件为 `WeaponMessageText`。
- 文字使用原生 `ACES-Regular`、字号 18、居中对齐，资源颜色为绿色，Alpha 为 0.5。该值不是原生运行时最终透明度的实测值。
- 面板直接挂在飞行 HUD 的 `CanvasPanel_0` 下，与普通消息的 `MessagePanel`、右下角统计区域分开。资源槽锚点在屏幕中心，垂直偏移为 210；这只是离线布局，不能外推成所有分辨率下的像素位置。
- 页面蓝图函数和调用摘要未发现武器提示专用的显示、隐藏或延迟函数；该页面只发现通讯头像动画 `ShowComPortraitAnimation_INST`，未发现武器提示专用动画。
- 因此“直接停止淡出动画”缺少依据。隐藏可能由原生 HUD 更新、计时、可见性或透明度驱动；不能从蓝图未发现动画就断言原生驱动机制已经确认。

详见[精简证据](../../evidence/native-weapon-message-structure.json)。完整资源副本和解析 JSON 只放在被忽略的 `Temp/` 中，不进入 Git。

## 推荐实现方向

### 显示控制

为这条提示明确建立独立显示控制，沿用原生 UMG 样式与锚点，文本采用右下角使用的武器简称。在正常 HUD 根容器中建立一次独立的提示控件，原生瞬时提示仅作为样式来源；接入时必须明确处理原提示，避免两份重叠显示。这是拟议实现方案，不是遇到接入错误时静默添加一份覆盖层。

独立控件保持正常显示，整体服从游戏的 HUD 显隐，不设半透明状态或淡出计时。不会每帧恢复原生控件可见性，也不会把整个消息父容器强制显示。复制文字控件不能复制其旧布局槽指针，生命周期处理可复用当前固定 SP 行的经验。

若后续定位到只管理武器提示的原生计时/隐藏入口，也可评估直接接管原控件；当前材料不足以确定该入口的安全范围。不要停止整个 HUD 的全部动画，通讯、警告等共享显示必须保留。

本机历史反射资料确认 `Widget:SetVisibility`，但没有较新 UE 的通用透明度 setter。中央使用文字自己的颜色接口和可见性，原瞬时提示使用折叠父容器隔离。

### 当前武器与简称

当前武器身份应由“MSL/SP + 逻辑 SP 选择”共同决定：MSL 为 0，SP1 为 1，SP2 为 2。不能只观察 `IsSpecialWeaponArmed()`，因为 SP1 → SP2 时此值仍可为真；也不能只观察核心 `active`，因为 MSL 状态下核心会预先载入另一种 SP，这不代表玩家切换了当前武器。

在原生键、F9 和核心切换事务完成后，根据最终选择更新提示。初始化或连续快速切换期间不展示中间武器。只有有效的当前武器变化才更新文本，内部预载入不能触发错误提示。

不需要记录显示起始时刻、计算停留时长或安排延迟回调。暂停时保留当前简称，整体显隐跟随原游戏。

文字需与右下角名称一致：MSL 固定为 `MSL`；SP1/SP2 复用 `native_hud.lua` 当前使用的 `options[weaponIndex+1].code:upper()` 生成简称，不再读取原生长说明作为显示内容。应共享简称生成规则，避免维护两份映射。不复制右下角文字的装填透明度，只复用文本；不能把隐藏后可能被清空的原生中央提示或旧 SP 内容当作事实来源。

## 与已有功能的兼容

| 功能 | 配合方式 |
|---|---|
| 右下角固定 SP1/SP2 行 | 使用独立控件与缓存，不改变现有排版和行身份 |
| 右下角装填/耗尽变淡 | 两者独立：右下角表示是否有弹可用，中央简称始终保持正常显示 |
| F8 与暂停 | 沿用暂停和输入隔离；无需显示计时，保留当前选择 |
| 中途补给与检查点 | 事务期间隐藏；完成后重新绑定最终武器，不显示旧选择 |
| 关闭 HUD、过场和任务退出 | 必须尊重全局显隐，恢复原提示并释放缓存 |

中央简称不随装填、耗尽或时间变化而变淡。右下角装填/耗尽变淡的先前需求保持不变，不因中央提示需求调整而取消。

现有任务 HUD 更新主要在双 SP 模式下运行。若此功能也要覆盖 SP2 为空的配置，需把中央提示调度从双 SP 行绘制条件中分离，不能让单 SP 出击失去该功能。

## 性能和仍待验证的部分

一次创建、缓存控件，复用当前每 100 毫秒的游戏线程调度。平时只比较当前武器，切换完成后才更新简称；全局显隐或生命周期变化时同步处理控件。无需新增持续文件快照、全局控件树扫描、武器槽遍历、兵装初始化或 DX11 渲染层，预计开销很小。

常驻内容只是一个原生文字控件；取消计时和渐变后逻辑更简单。不能把预计开销小写成“已证明零性能影响”。

主要未验证项是原生隐藏机制、HUD 全局显隐与不同任务中的时序。简称较长说明更少占用视野；建议保留独立开关和原位置，不增加背景面板。按新要求不增加透明度或亮显时长设置。

后续实玩需核对 MSL → SP1 → SP2 → MSL、原生键和 F9、快速连切、暂停、零弹药跳过、单 SP 配置、补给、检查点、过场、HUD 开关及任务退出。此列表是后续验收范围，本轮没有自动运行测试。
