# 视角保持的平滑与连续环绕研究

## 范围和依据

2026-10-26用户反馈转动仍不够平滑，看到正后方约180°后不能继续转动，希望视角保持开启时可自由360°环绕。当时基线为正式2.26.1/main `800f858`，研究分支为`codex/research-camera-orbit-smoothing`；先分析源码和既有回执，并完成用户授权的只读采集。2026-10-30的新要求和当前候选见下文，不改版本、配置协议或玩家文案，不编译、写/运行测试、安装或替用户操作游戏。

用户确认主要使用手柄右摇杆，先要求水平连续环绕，随后补充第一/第三人称的垂直连续环绕，并要求普通座舱恢复原生角度限制。此前VR5°候选`1c9f68b`及文案决定`5cd8df0`的来源和接收情况以工作区登记及主线为准。

主要依据为[src/camera_hold.hpp](../../src/camera_hold.hpp)的`cameraHoldMoveStick`、`cameraHoldUpdate`、`cameraHoldObservePad`及两个输出入口，以及[原始镜头研究](../../evidence/camera-hold-research.json)、[输入覆盖](../../evidence/camera-input-coverage.json)、[注视衔接](../../evidence/tracking-view-continuity.json)。旧现场只证明当时采集条件，不作为当前反馈的动态根因或新效果验收。

## 正式2.26.1的水平限位

基线模组用归一化水平状态`x`保存方向，摇杆角位移除以180°后叠加：

- `cameraHoldMoveStick`发现`nextX`越过`[-1,1]`就清零水平速度，并把结果夹回该范围。
- `cameraHoldUpdate`前后均要求原生状态绝对值不超过1.01；更新后再次把`poseX`夹到`[-1,1]`。
- 普通换视角继续传递这个有限范围姿态，没有独立的连续水平角。

所以“到正后方停止”首先有明确的模组限位依据，并非已证明游戏只能看180°。把这一个钳位删掉仍不完整：其他状态校验、保存、原生输入范围和输出计算仍假定有限区间。直接在+180°换成−180°也须确认原生输出/插值按同一方向穿过后方，否则可能反向绕转或跳变。

原生第一/第三人称输入会把轴夹到约±0.95再归一化，普通座舱另有范围计算；这是旧采集记录支持的接口契约。基线源码还保留座舱特殊/委托路径以及`0x424200`的方向范围查询，不能据第一/第三人称状态推定座舱的实际角度与边界相同。

## 基线平滑处理与现场疑点

基线摇杆分支已采用25毫秒响应的角速度解析积分；≤100毫秒使用完整游戏delta，更长停顿清速度。它不是简单按帧累加固定步长。相同恒定输入下，不能只凭“不平滑”反馈认定该积分公式错误，也不建议直接继续加长滤波而增加跟手延迟。

值得先核对以下输入交接：

| 基线源码 | 静态推断与尚缺的证据 |
|---|---|
| 物理右杆以8192圆形门槛识别来源，实际环视轴以0.001门槛判断活动 | 两者并非同一死区定义；小幅输入附近可能来回进出两条路径，需要对应输入样本确认 |
| 物理右杆状态来自游戏线程允许的XInput观察及约20毫秒Lua补采；环视轴在每次相机更新读取 | 同一次更新可能混用不同时间的物理/引擎轴状态，不能声称每帧都取得同步原始采样 |
| 只有摇杆活动或松杆收尾进入角速度分支，其他情况走原生路径并清速度 | 进入/退出分支时可能发生速度交接；源码上的可能性不是本次卡顿已定位 |
| 键鼠单独环视继续原生响应，未共享摇杆的25毫秒积分 | 若反馈主要来自鼠标飞控或原生鼠标，单改摇杆响应参数无法证明有效 |
| 原生输出、注视/退出插值、座舱边界和机体运动继续参与最终画面 | 即使输入角速度均匀，也不保证屏幕最终观感等速；须区分相机曲线、帧时间和第三方输入来源 |

主线2.26.1已有相机资格复用及读取批次优化。本研究不为手感问题撤回身份保护，也不把历史性能反馈当作本次输入根因。新采集覆盖右杆和原生输入轴，但没有游戏帧时间、当前模组分支选择及每帧delta，仍不能区分速度曲线、来源切换与实际渲染卡顿。

## 水平环绕的来源与当前修订

唯一实现为[src/camera_hold.hpp](../../src/camera_hold.hpp)，不改Lua调用、按键配置、NEXT模式或白点逻辑。沿用原有默认开关和灵敏度：右杆相对环绕只在视角保持开启、当前玩家/输入/普通视角及游戏线程资格有效时生效。

### 连续水平角与右杆交接

- `stickYaw/stickPitch`使用独立双精度角状态，不再逐帧从原生浮点水平姿态重建积分。水平越过±180°不清速度，交给原生时用等价角折回一圈；水平角绝对值超过1024圈后只减去整圈数，避免无界增长损失精度。原水平候选保留±90°俯仰；本次第一/第三人称的垂直扩展见下文。
- 保留25毫秒解析角速度响应、灵敏度及斜向合成限速；≤100毫秒按完整delta积分，超过100毫秒清速度、不补走停顿。松杆后保持同一路径衰减到零；普通换视角保存角度、速度及来源交接时间，不重启滤波或跳过一帧积分。
- 当前普通视角的输入更新主动查询一次XInput，不再只依赖约20毫秒Lua补采；引擎轴和查询仍非原子快照。来源初次以8192圆形门槛识别，接管后用4096退出参考及50毫秒交接窗防抖；实际命令、映射、死区、竖轴反转仍来自原生轴。零轴保持可继续积分收尾，键鼠单独活动超过交接条件后回原有绝对角路径，不修改原生键位。
- 第一/第三人称仍将等价角转换为原生±0.95输入。只在没有注视/退出权重的相对环视路径使用原有`delta*7=1`消费已积分姿态，避免再追近一次；原生输出继续负责最终旋转及位置。真实注视、特殊委托及其他输入继续使用真实delta。

### 普通座舱输出

历史水平环绕候选曾替换普通座舱输出基底，使其突破原生环视轨迹范围。2026-10-30用户明确要求撤回座舱解限；本次候选移除该基底旋转和临时置零，直接使用原生`0x424610`输出及座舱动画轨迹。右杆积分在原生输入范围两端停止，不在边界折返；原生飞行状态限制及座舱注视插值继续执行。进入座舱时不继承第一/第三人称的多圈俯仰，改用座舱有限姿态，越界朝向不能保证跨视角完全连续。

### 回正、视角切换和状态归还

- 第一/第三人称和普通座舱共享同一归一化参考方向。若目标视角的输出早于首个输入更新，先向当前输入组件接续已保存姿态；不修改机体旋转或世界位置。
- L3仍为回正，R3短按换视角、长按0.3秒切换视角保持；不增加新快捷键，也不恢复角度自动回正。水平角传给原生的是当前一圈内的表示，因此回正不追赶已经转过的整圈。
- 普通座舱回正及关闭保持归还原生座舱轨迹；第一/第三人称保留连续俯仰并向最近的回中方向过渡。关闭保持不顺带关闭独立锁定注视；显式回正继续沿用结束模组锁定注视的原规则。
- 注视和退出权重期间暂停相对角速度，目标/进度混合仍走原生。暂停、失焦、断连、换机、心跳过期、特殊镜头及故障继续清理姿态/速度和旧输入，不继承上一玩家状态。

新增工作为当前相机的一次XInput查询和固定数量角度运算；第一/第三人称垂直输出还需暂存并恢复两个输入字段，普通座舱不再复制替换基底。没有目标遍历、全局对象扫描、新线程、逐帧磁盘或日志。尚未编译或计量，不能据静态规模保证FPS不变或FPS游戏同等手感。

基于main `cf49fc0`建立`codex/fix-camera-vertical-cockpit`。新分支在核对相机源文件与原候选基线相同后，精确接续`962d35a`的第一/第三人称垂直连续角：保留双精度俯仰和速度，输入向原生有限范围折回，在第一/第三人称输出期间暂时提供完整俯仰，返回后恢复原始输入状态。原生输出仍负责相机变换和目标注视，不在注视混合后额外旋转结果。原生俯仰读取指令和90°常量已在当前进程只读核对，运行接入时也校验；特殊/委托镜头继续原生。关闭保持及L3回正从一圈内方向渐进回中，普通视角切换接续俯仰。
