# 视角保持的平滑与连续环绕研究

## 范围和依据

2026-10-26用户反馈转动仍不够平滑，看到正后方约180°后不能继续转动，希望视角保持开启时可自由360°环绕。基线为正式2.26.1/main `800f858`，研究分支`codex/research-camera-orbit-smoothing`。本轮分析源码、既有回执及用户授权的现场只读采集，未修改运行代码、版本、配置或玩家文案；不编译、写/运行测试、安装或替用户操作游戏。

用户已确认主要使用手柄右摇杆，问题出现在所有普通视角；360°按提问中的“水平连续旋转，可越过正后方并继续转多圈”继续研究，不扩大为垂直翻转，也不把范围确认写成全部机型座舱已实现无限制。此前VR5°候选`1c9f68b`及文案决定`5cd8df0`留在独立分支，未整套带入本研究或main。

主要依据为[src/camera_hold.hpp](../../src/camera_hold.hpp)的`cameraHoldMoveStick`、`cameraHoldUpdate`、`cameraHoldObservePad`及两个输出入口，以及[原始镜头研究](../../evidence/camera-hold-research.json)、[输入覆盖](../../evidence/camera-input-coverage.json)、[注视衔接](../../evidence/tracking-view-continuity.json)。旧现场只证明当时采集条件，不作为当前反馈的动态根因或新效果验收。

## 已确认的水平限位

当前模组用归一化水平状态`x`保存方向，摇杆角位移除以180°后叠加：

- `cameraHoldMoveStick`发现`nextX`越过`[-1,1]`就清零水平速度，并把结果夹回该范围。
- `cameraHoldUpdate`前后均要求原生状态绝对值不超过1.01；更新后再次把`poseX`夹到`[-1,1]`。
- 普通换视角继续传递这个有限范围姿态，没有独立的连续水平角。

所以“到正后方停止”首先有明确的模组限位依据，并非已证明游戏只能看180°。把这一个钳位删掉仍不完整：其他状态校验、保存、原生输入范围和输出计算仍假定有限区间。直接在+180°换成−180°也须确认原生输出/插值按同一方向穿过后方，否则可能反向绕转或跳变。

原生第一/第三人称输入会把轴夹到约±0.95再归一化，普通座舱另有范围计算；这是旧采集记录支持的接口契约。当前源码还保留座舱特殊/委托路径以及`0x424200`的方向范围查询，不能据第一/第三人称状态推定座舱的实际角度与边界相同。

## 平滑处理的现状与疑点

现有摇杆分支已采用25毫秒响应的角速度解析积分；≤100毫秒使用完整游戏delta，更长停顿清速度。它不是简单按帧累加固定步长。相同恒定输入下，不能只凭“不平滑”反馈认定该积分公式错误，也不建议直接继续加长滤波而增加跟手延迟。

值得先核对以下输入交接：

| 源码现状 | 静态推断与尚缺的证据 |
|---|---|
| 物理右杆以8192圆形门槛识别来源，实际环视轴以0.001门槛判断活动 | 两者并非同一死区定义；小幅输入附近可能来回进出两条路径，需要对应输入样本确认 |
| 物理右杆状态来自游戏线程允许的XInput观察及约20毫秒Lua补采；环视轴在每次相机更新读取 | 同一次更新可能混用不同时间的物理/引擎轴状态，不能声称每帧都取得同步原始采样 |
| 只有摇杆活动或松杆收尾进入角速度分支，其他情况走原生路径并清速度 | 进入/退出分支时可能发生速度交接；源码上的可能性不是本次卡顿已定位 |
| 键鼠单独环视继续原生响应，未共享摇杆的25毫秒积分 | 若反馈主要来自鼠标飞控或原生鼠标，单改摇杆响应参数无法证明有效 |
| 原生输出、注视/退出插值、座舱边界和机体运动继续参与最终画面 | 即使输入角速度均匀，也不保证屏幕最终观感等速；须区分相机曲线、帧时间和第三方输入来源 |

主线2.26.1已有相机资格复用及读取批次优化。本研究不为手感问题撤回身份保护，也不把历史性能反馈当作本次输入根因。新采集覆盖右杆和原生输入轴，但没有游戏帧时间、当前模组分支选择及每帧delta，仍不能区分速度曲线、来源切换与实际渲染卡顿。

## 可行实现方向

1. **先统一输入与速度交接。** 在当前普通相机更新的正确线程获取一致输入，避免使用不同死区/时间的状态反复切换绝对追近和相对角速度路径；保持小幅输入、松杆及反向操作连续。以用户已确认的右摇杆为优化对象，继续区分原生键鼠和鼠标飞控，不全局更改第三方Mod或盲目共用过滤参数。
2. **增加独立连续水平角。** 模组维护不受±180°钳位的水平角/转动速度，原生需要有限表示时才归一化，并正确处理正后方两侧的等价方向。状态保存、换视角及交接都须基于同一方向，不能一处取余后又被另一处钳位或清速度。
3. **核对输入到输出的完整路径。** 第一/第三人称公共输出`0x41e350`已确认按水平状态×180°、竖直状态×90°构造旋转；普通分支再转换为四元数/变换，具有水平角周期表示的基础。可优先研究仅在相对角速度分支以等价角跨界，保留速度且避免原生再次追近。座舱`0x424610`调用`0x423630`，将归一化环视映射到相机动画轨迹并混合变换，不能套用简单的×180°关系。座舱须另行建立连续参考方向与输出衔接；不先改全局代码常量或承诺所有特殊座舱通用。
4. **保持操作边界。** 仅视角保持开启时允许连续环绕；关闭后交还原生。L3回正走平滑的合理方向，R3普通视角切换、锁定注视进入/退出、5°白点及VR门槛读取的实际朝向都须衔接。暂停、失焦、断连、换机和特殊镜头清理旧角度/速度，不能继承上一玩家状态。

新增角度与速度数学可保持每帧固定规模，不需要目标遍历、全局对象扫描、新线程、逐帧磁盘或日志；但实际输出接点、读取次数和不同帧率成本尚未测量。不能据静态设计保证FPS不变或FPS游戏同等手感。

## 本次现场只读依据

用户允许自行启动游戏、进入任务并转动视角后只读观察，随后明确“已准备好，现在采集”。读取器只用查询/读内存权限和XInput查询；核对游戏路径、构建指纹、对象身份及玩家控制器归属，不调用游戏函数、不写游戏内存、不注入按键。对象换代或所属关系改变即停止。一次准备阶段没有找到实际玩家，识别条件复核后成功识别F-35C；该次失败未产生状态记录，不据此猜地址。

| 现场 | 记录与边界 |
|---|---|
| 首轮45秒 | 4500条，只有第三人称，没有有效右杆位移；不用于判断转动手感 |
| 配合后的30秒 | 3000条，第三人称，757条达到右杆活动门槛；持续向右推时水平状态在+1停留约0.63秒，向左推时在−1停留约0.59秒，反向后离开边界 |
| 随后的60秒 | 6000条，第一人称843条、第三人称5157条；1166条达到右杆活动门槛。第一人称在−1、+1边界各停留约0.41秒，期间仍向边界方向推杆；第三人称也再次出现+1停留 |

上述边界区间要求归一化状态绝对值>0.9999且输入仍向该侧，时长来自外部采样，不是游戏帧计数。第一/第三人称的实际相机视线经机体四元数逆旋转后，水平角整体符合归一化状态×180°；顺序跨进程读取、机体运动和镜头曲线使瞬时误差不能当作原生单帧插值。动态结果支持源码限位定位，不证明取消限位后的跨界效果已经验证。

两轮有效记录中，外部物理右杆门槛与原生环视轴活动判断分别有3条、16条不一致。这既可能包含采样时差，也可能包含死区差异，**不能据此认定它们就是卡顿根因**。本轮没有获取游戏帧时间或进行FPS对照；读取器每条采样自身耗时中位数约0.14/0.17毫秒，只说明外部采集开销，不换算为模组成本或帧率影响。采集未覆盖座舱，不能把第一/第三人称的现场结论扩写为座舱已验证。

## 结论与继续条件

**可以继续优化；水平连续360°没有被现有依据证明为引擎硬限制。** 第一/第三人称已有直接的角度映射与动态限位证据，适合采用持续角速度、等价角跨界及统一状态交接。座舱有独立动画轨迹，必须单独处理输出，不能用“去掉一处clamp”覆盖所有普通视角。平滑优化应优先保证相对角速度分支连续、输入采样/来源判定一致，保留现有25毫秒解析响应，不能凭观感承诺增加滤波就能解决。

当前完成的是研究和现场只读核对，**尚未实现平滑修订或360°功能**。下一步在独立分支限定`camera_hold.hpp`的连续角状态、输入交接及普通输出衔接，再做静态审阅；不改原生全局常量或特殊委托。此前VR5°候选保持独立，本研究基线尚不包含它。

后续获准验证时须覆盖连续跨后方、同向多圈、反向与松杆、各普通视角/座舱、注视/L3回正/R3切视角，以及暂停/失焦/换机的状态归还。本次只读观察不是新功能的实机验收；始终不编译、测试或安装。若最终涉及玩家中文说明，继续按逐条审核规则处理。
