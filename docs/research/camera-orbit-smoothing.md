# 视角保持的平滑与连续环绕研究

## 范围和依据

2026-10-26用户反馈转动仍不够平滑，看到正后方约180°后不能继续转动，希望视角保持开启时可自由360°环绕。基线为正式2.26.1/main `800f858`，研究分支`codex/research-camera-orbit-smoothing`。本轮只读分析源码和既有回执，未修改运行代码、版本、配置或玩家文案；不编译、写/运行测试、安装或操作游戏。

用户已确认主要使用手柄右摇杆，问题出现在所有普通视角；360°按提问中的“水平连续旋转，可越过正后方并继续转多圈”继续研究，不扩大为垂直翻转，也不把范围确认写成全部机型座舱已实现无限制。此前VR5°候选`1c9f68b`及文案决定`5cd8df0`留在独立分支，未整套带入本研究或main。

主要依据为[src/camera_hold.hpp](../../src/camera_hold.hpp)的`cameraHoldMoveStick`、`cameraHoldUpdate`、`cameraHoldObservePad`及两个输出入口，以及[原始镜头研究](../../evidence/camera-hold-research.json)、[输入覆盖](../../evidence/camera-input-coverage.json)、[注视衔接](../../evidence/tracking-view-continuity.json)。旧现场只证明当时采集条件，不作为当前反馈的动态根因或新效果验收。

## 已确认的水平限位

当前模组用归一化水平状态`x`保存方向，摇杆角位移除以180°后叠加：

- `cameraHoldMoveStick`发现`nextX`越过`[-1,1]`就清零水平速度，并把结果夹回该范围。
- `cameraHoldUpdate`前后均要求原生状态绝对值不超过1.01；更新后再次把`poseX`夹到`[-1,1]`。
- 普通换视角继续传递这个有限范围姿态，没有独立的连续水平角。

所以“到正后方停止”首先有明确的模组限位依据，并非已证明游戏只能看180°。把这一个钳位删掉仍不完整：其他状态校验、保存、原生输入范围和输出计算仍假定有限区间。直接在+180°换成−180°也须确认原生输出/插值按同一方向穿过后方，否则可能反向绕转或跳变。

原生第一/第三人称输入会把轴夹到约±0.95再归一化，普通座舱另有范围计算；这是旧采集记录支持的接口契约。当前源码还保留座舱特殊/委托路径以及`0x424200`的方向范围查询，不能据第一/第三人称状态推定座舱的实际角度与边界相同。

## 平滑处理的现状与疑点

现有摇杆分支已采用25毫秒响应的角速度解析积分；≤100毫秒使用完整游戏delta，更长停顿清速度。它不是简单按帧累加固定步长。相同恒定输入下，不能只凭“不平滑”反馈认定该积分公式错误，也不建议直接继续加长滤波而增加跟手延迟。

值得先核对以下输入交接：

| 源码现状 | 静态推断与尚缺的证据 |
|---|---|
| 物理右杆以8192圆形门槛识别来源，实际环视轴以0.001门槛判断活动 | 两者并非同一死区定义；小幅输入附近可能来回进出两条路径，需要对应输入样本确认 |
| 物理右杆状态来自游戏线程允许的XInput观察及约20毫秒Lua补采；环视轴在每次相机更新读取 | 同一次更新可能混用不同时间的物理/引擎轴状态，不能声称每帧都取得同步原始采样 |
| 只有摇杆活动或松杆收尾进入角速度分支，其他情况走原生路径并清速度 | 进入/退出分支时可能发生速度交接；源码上的可能性不是本次卡顿已定位 |
| 键鼠单独环视继续原生响应，未共享摇杆的25毫秒积分 | 若反馈主要来自鼠标飞控或原生鼠标，单改摇杆响应参数无法证明有效 |
| 原生输出、注视/退出插值、座舱边界和机体运动继续参与最终画面 | 即使输入角速度均匀，也不保证屏幕最终观感等速；须区分相机曲线、帧时间和第三方输入来源 |

主线2.26.1已有相机资格复用及读取批次优化。本研究不为手感问题撤回身份保护，也不把历史性能反馈当作本次输入根因。没有新帧时间或输入采样，暂不能区分速度曲线、来源切换与实际渲染卡顿。

## 可行实现方向

1. **先统一输入与速度交接。** 在当前普通相机更新的正确线程获取一致输入，避免使用不同死区/时间的状态反复切换绝对追近和相对角速度路径；保持小幅输入、松杆及反向操作连续。用户确认设备后区分摇杆、原生键鼠和鼠标飞控，不全局更改第三方Mod或盲目共用过滤参数。
2. **增加独立连续水平角。** 模组维护不受±180°钳位的水平角/转动速度，原生需要有限表示时才归一化，并正确处理正后方两侧的等价方向。状态保存、换视角及交接都须基于同一方向，不能一处取余后又被另一处钳位或清速度。
3. **核对输入到输出的完整路径。** 第一/第三人称已有公共输出入口`0x41e350`，座舱另走`0x424610`及机型范围。先确认后方跨界时的实际角度映射/插值，再决定能否只调整输入表示，或必须在受限作用域补输出衔接；不先改全局代码常量或承诺所有特殊座舱通用。
4. **保持操作边界。** 仅视角保持开启时允许连续环绕；关闭后交还原生。L3回正走平滑的合理方向，R3普通视角切换、锁定注视进入/退出、5°白点及VR门槛读取的实际朝向都须衔接。暂停、失焦、断连、换机和特殊镜头清理旧角度/速度，不能继承上一玩家状态。

新增角度与速度数学可保持每帧固定规模，不需要目标遍历、全局对象扫描、新线程、逐帧磁盘或日志；但实际输出接点、读取次数和不同帧率成本尚未测量。不能据静态设计保证FPS不变或FPS游戏同等手感。
