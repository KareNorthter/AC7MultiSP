AC7DualSP 三 SP 研究候选 1
版本：1.0.2-three-sp-candidate.1
日期：2026-10-15
分支：codex/three-sp-research
基线：1.0.2，运行逻辑源于 839eb80；发布整理提交 5628a62。

状态
本候选以现有单人 1.0.2 为基础，扩展 1 至 3 个 SP 的选择、出击、切换、补给与检查点。
它是可安装的研究候选，不是已经实玩验证的正式版。
构建、语法与载荷核验见 evidence/three-sp-candidate-build.json；不能据此判定飞行或三栏布局已通过。
本次生成独立增量目录；未部署，不停止或启动当前游戏，不制作 ZIP，不推送。

研究结论与实现
1. 原生机体有三个 SpecialWeaponConfig，可通过现有 InitializeWeaponSystem(index) 选择 0/1/2。
   1.0.2 已能将其中任意两个组合使用，因此第三个配置不需要新增游戏武器资源。
   三槽仍是轮流重建当前活动 SP，分别缓存状态；不是同时运行三个原生武器系统。
2. 核心旧 Session.special/maximum 固定两项，命令只接受两种配置。
   本候选改为最多三槽、显式 count/configs；原生命令协议 3 拒绝旧格式。
   每槽独立保存弹药、装填队列和时间；普通导弹、机炮、干扰弹继续保存。
3. 原生准备页和补给页扩展为 SP1 → SP2 → SP3。
   SP1 必选；SP2 选择 NO WEAPON 结束为单挂；SP3 选择 NO WEAPON 结束为双挂。
   每槽只能选择未在前槽使用且已购买的武器；返回修改上一槽，后续重新确认。
   准备页完成后仍由真实原生确认进入 STANDBY；补给最后保留 YES/NO，默认 NO。
   补给成功后才提交配置，不在光标预览或 YES 按下时提前换装。
4. 用户明确采用自动均分：单挂全量，双挂各 1/2，三挂各 1/3。
   各武器先计算自己的部件后完整载量，再按数量向下取整；正载量至少一发，零仍为零。
   例：完整载量 30/18/7 时，三挂得到 10/6/2。不同武器不是共用同一个弹药池。
   去掉管理界面的 50%–100% 滑块；不存在可编辑的任意配弹比例。
5. 单挂同样纳入核心快照，支持补给在 1/2/3 槽之间变更后恢复旧检查点的原方案。
   检查点自己的槽数、配置、弹药与时间一起恢复，不能套用补给后的新方案。
6. HUD 为 MSL + 实际搭载的 SP1/SP2/SP3；空槽不占行。
   核心就绪接口返回普通导弹与三槽的独立状态；中央简称跟随最终活动槽。
   正常等待显示三槽占位，沿用 1.0.2 的模型身份、世界校验、10 秒超时和明确失败路径。
   原生选装与补给在原两栏总宽内排列三栏；STANDBY/PART 将原两张卡片范围改为三张紧凑卡片。
7. 键盘默认 1/2/3/4 对应 MSL/SP1/SP2/SP3，可在管理界面修改；手柄为十字键左/上/右/下。
   原生循环键按 MSL → SP1 → SP2 → SP3 → MSL 循环，跳过耗尽槽。
   管理协议与参数版本为 3。管理键新配置默认 F6，保留既有明确键值（包括旧 F8）；Back+Y 不变。
8. SP2 沿用用户提供的 WAV；SP3 明确复用原生 SP 提示音，没有新增 SP3 语音。

安装（增量候选，仅供已正确安装本项目 1.0.2 的本机使用）
1. 退出游戏，完整备份游戏目录 ue4ss/Mods/DualSP，尤其是 profiles.json。
2. 将本目录 GameFiles 中的内容复制到含 Ace7Game.exe 的游戏根目录，成套覆盖 DualSP 的运行文件。
   不单独复制 Lua、核心或 UI；三个部分含相互校验的三 SP 接口。
   不替换加载器、不改 mods.txt、不改第三方 PAK、不复制个人配置与存档。
3. 启动后 schema=1 的旧配置会先保留 profiles.before-three-sp.json，再升级为 schema=2。
   旧机体方案的 SP1/SP2 不变，SP3 为空；旧比例改为按数量均分。
   保留旧语言、中央提示与管理键；新增 SP3 键为 4。若旧自定义键已占用 4，明确停止迁移，需先调整旧键位。
   有同名迁移备份但仍是旧 schema 时也会明确停下，需核对上次迁移状态，不能覆盖备份。
4. 先进入原生机库重新确认所选数量，再由用户自行出击。

项目内也可使用受控安装入口：
python -X utf8 src/install-resupply-candidate.py --three-sp
该入口要求已生成候选清单、游戏已经关闭；核对核心/UI/Lua、加载器、配置与存档，整目录备份后安装，不自动启动。
prepare-three-sp-candidate.py 只核验和整理，不执行安装。构建使用既有独立核心/UI 构建入口。

回退
退出游戏，将当前候选目录移到备份位置，再恢复安装前完整的 DualSP 目录。
必须同时恢复原 Lua、核心、UI、VERSION 和 schema=1 的配置；不要让 1.0.2 读取 schema=2。
使用受控安装器时，以安装回执中的 backup 路径恢复整套目录。
正式 1.0.2 ZIP 及其文件清单保持不变；本候选目录不包含新手所需的加载器或运行库。

首轮实玩清单（用户执行；代理不自动开始任务或发射武器）
• 使用有三种已购买且允许多挂 SP 的原版机体，依次确认单挂、双挂、三挂，观察等待/返回/重选和 STANDBY/PART。
• 检查 30/18/7 等不可完全整除的载量、增弹部件后的菜单预览与任务实际弹药是否一致。
• 三挂出击，分别使用原生循环键和 1/2/3/4；检查每槽消耗、装填、耗尽跳过及不回满。
• 检查 HUD 三行 SP、选择箭头、中央简称、过场显隐；留意英文长名称及不同分辨率的裁切。
• 补给三挂改双挂、单挂改三挂、三挂改单挂；验证 NO/返回不会提交，YES 成功后才应用。
• 捕获检查点后补给改变槽数，再重来，核对回到检查点原方案与弹药，而非最后一次补给方案。
• 最后验证 TLS 收尾、J-20/Adler 等外部机体；已有双 SP 兼容结论不能直接当作三 SP 通过。

仍保留的限制
UAV/ECM 仅允许单挂，不能因增加第三槽放宽生命周期限制。
只显示当前一种 SP 模型，普通导弹保留上一 SP 模型；不承诺三种外挂模型同时可见。
不解除购买或 DLC 限制，不支持多人/VR；自定义无限弹药及特殊武器生命周期不保证兼容。
单挂改用统一核心快照、三槽连续重建和三栏紧凑布局都是新增待实玩内容。
