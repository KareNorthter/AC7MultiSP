# 当前架构

本文说明整理基线 `39141fd` 的运行机制。正式发布、本机安装和独立候选的当前状态只在[项目入口](../../README.md)维护；历史 `2.25.x / 2.26.x` 是已接收研究阶段编号，不能按数字判断正式版本先后。原始记录见[evidence索引](../../evidence/README.md)，旧方案从[研究索引](../research/README.md)与[归档索引](../archive/README.md)恢复。

适用基线为 Steam build 9855922、Windows 10/11 x64 的单人战役与自由任务。源码保留未启用的弹舱动画等研究基础设施，保留文件不等于启用相应方案。

## 模块职责

Lua 在游戏线程确认模式、世界、实际玩家和原生交接，再向核心提交事务。核心负责兵装会话与独立视觉状态；渲染线程读取快照、绘制界面和排队动作，不访问游戏对象。

## 许可与事务边界

总开关关闭、多人或模式尚未确认时不接管兵装。总开关只在允许输入的主菜单/单人任务选择等安全入口应用；在任务、补给或机库保存时等待安全入口。第13关任务 ID `113` 旁路兵装、模型和 HUD，保留原生指定 SP、选装与检查点；自由飞行 `213` 不命中，离开该关后重新建会话。镜头功能有独立许可。

兵装显示简称由`weapon_names.lua`统一提供。原版Morgan、XFA-27、CFA-44及Super Kai的IEWS内部均使用`ecm`目录代号；运行时严格按实际兵装完整类路径显示IEWS，快速目录还核对原版机体完整引用及三槽签名。Super Kai对应`/Game/Blueprint/Weapons/Player/Variation/plwp_ecmp_j0.plwp_ecmp_j0_C`，三槽为LASM/6AAM/ecm。本次只补显示白名单，不改效果、内部键、资格或Mod自定义名称。名称核查来源见[接收回执](../../evidence/2.26.2-latest-source-and-management-review.json)。

### 机体故障退让与F6诊断（alpha2候选）

`codex/feat-aircraft-fault-recovery`基于main/9075581，按[总体规则](../project/workflow.md#故障隔离与恢复)补齐统一退让。单人环境确认许可与增强许可分离：资料不完整、已隔离机体停止全部增强调度，但UI门禁保持开放；诊断模式只消费打开/关闭管理页及保存设置，不调用换机、快速任务、兵装或镜头接口，也不尝试取得原生暂停。多人和未知环境仍关闭界面许可，不能借诊断模式绕过原有边界。

运行错误先保留机体编号及首个原因，以本次游戏的机体隔离表拒绝再次接管。发生在任务内或补给中的错误保留退出任务要求，不能把已修改的库存假称原生状态；必须回到已确认的任务外菜单并选择另一机体才解除该要求，再按原资格重新建立会话，并清除旧会话的增强功能失败标记，不重放旧输入。隔离不改配置总开关、方案或版本号；保存设置不解除隔离。退让清理采用严格失败回报，原生页面、HUD或输入归还失败不能仅写日志后冒充清理完成；历史调用仍保留原默认行为。

上下文/清理失败、无法确认机体归属以及核心已有的进程级持续效果故障升级为严重错误：锁住增强功能到重启，独立尽力归还核心、输入、页面和HUD；F6在仍能确认的单人环境开放，显示重启提示和原因。严重故障后只每250ms确认一次显示环境，反射菜单事件可立即关闭多人入口，不重跑增强初始化或清理。界面/发布本身失效、脚本加载前的接口或配置断言失败仍可能只留下日志，本轮尚未提供独立启动诊断宿主。

目录仍走只读游戏线程接口，新增`_compat.weapon_issues`逐槽保留机体编号、代号、SP槽、兵装代号、稳定原因键和日志原文；正常的`-1`空槽只保留不支持状态，不冒充缺失错误。目录行身份错误及重复编号另记；无法取得有效编号的条目只能报告，不能凭猜测禁用另一机体。原`_compat.schema=1`和管理协议22不变，新增`dualsp_aircraft_recovery_supported`要求核心、UI、Lua成套，防止旧组件忽略诊断字段。

F6第一页在有异常时提供详情按钮，弹出可滚动独立窗口，关闭总开关及当前机体退让后仍可阅读。异常详情仅在管理页打开时发布；关闭时轻量状态只带异常数和恢复说明。所有新增中文界面词条已由作者确认后写入唯一文字源，英文同步生成；机体名缺失时显示目录代号及编号，不加载全部蓝图补名称。

首个已确认安全菜单在目录就绪后显示三秒加载提示，读取实际版本和已保存快捷键，有异常时附异常数量；更新状态不混入该通知。每次发起的检查得到最新/新版/失败/未发布的最终结果后，在任务外单独播放一次三秒通知，等待和检查中不播放。继续沿用网络超时、下载白名单及关闭自动检查的配置，不阻塞游戏线程或等待联网完成。

研究接收后已构建alpha2常规/开发候选并补齐受控故障入口；作者确认修正版快速五轮通过，具体范围及扩展待测见[测试指导](aircraft-fault-testing.md)。原研究阶段回执不回改。现有可独立退让的历史子模块不在本轮全部重写；不会据本轮断言所有错误均已统一隔离或完全恢复原生。

| 阶段 | 提交与清理 |
|---|---|
| 准备页 | SP1/SP2/SP3 为独立草稿，真实确认进入 STANDBY 才保存；取消不提交 |
| 补给 | 核对独立页面/玩家身份，最终确认默认 NO，原生起飞成功后重建并保存 |
| 切换 | 保存各 SP 库存、装填队列及游戏时间，原生重建后恢复；保留普通导弹、机炮和干扰弹 |
| 检查点 | 独立持有方案与会话，后续补给/调试不能改写旧快照 |
| 任务调试 | 重配并补满 SP，保留个人方案、普通弹药与旧检查点；活动兵装可阻止重配 |
| 离页/换机/换世界 | 归还自有控件、输入、模型和动画责任，清除旧身份与未消费动作 |

原生循环与直选共用最终事务，不发布内部 MSL 中间态。内部重建不重排自身输入。真实在途、未知或失效武器引用阻止组合重建；仅已核身份、玩家归属、非活动标记及原生 Bomb 父类的停用炸弹可作为残留忽略，另保留既有 Raven/UAV 例外，不清原生数组强行放行。

本分支待接收的长按兼容修复：内部MSL/SP转换及SP重建后的类别恢复，共用完整飞机入口`0x82a730(plane,true)`；原生该参数只跳过尾部DropTank按住标志及计时初始化，门禁、类别和锁定参数更新仍执行。内部不再调用真实Pressed/Released，也不保存、重放或改写玩家的按住状态；真实输入及其原生附加功能继续由游戏处理。调用前核对游戏线程及玩家会话，两段完整原生函数首次按Steam 9855922采样指纹校验，兵装重建前预检；指纹不符即拒绝。来源、未编译/安装/实测边界见[源码修复回执](../../evidence/mod-aircraft-hold-switch-fix-source-20261024.json)。

每次模组兵装重建前通过原生逐槽 Reset 解除锁定、停音，再清理旧版本留下的无主登记，防止旧 LockedTargets 污染新批次；不直接清目标数组、不修改正常多目标发射数量。该共同路径的修复依据见[现场记录](../../evidence/cfa44-live-seeker-residue.json)，不据此保证所有机体的双发现象均已消除。

## 进程内通信与文件边界

本轮2.26.1 alpha1候选将F6大列表与轻量状态分开：Lua仅在管理页打开时刷新换机、快速任务机体/皮肤与任务列表，按来源表身份变化发送`management_lists`。普通飞行及兵装切换仍及时发布HUD、设置、许可和事务回执，但不再编码旧列表。UI接收端在短锁内分别交换三份不可变列表及轻量状态，轻量快照覆盖不会丢掉尚未消费的列表；渲染侧按共享身份保有列表，换机选项只在列表变化时重新解析。新增`dualsp_ui_lists_supported`要求Lua/UI成套，旧组件不能静默混装。列表仅用于显示，换机/快速任务提交仍执行原有实时身份、许可及目标核对，不能以列表缓存绕过检查。

2.26.1 alpha2在成功的即时HUD刷新后更新周期时间戳，避免当轮后续100ms调度重复采样。切换和重建的即时调用保留；不合并不同选择事务。新增`preview_total`（Lua准备及原生预览）、`native_switch`（含资源检查及兵装请求）、`flight_mount`、`hud`四项15秒汇总；`preview_native`包含在`preview_total`中，仍不可相加。评估和用户测试方法见[性能评估](../research/runtime-performance.md)。

候选沿用`PERF_STAGE`统计并新增`publish_encode`、`publish_submit`两项，分别覆盖Lua JSON编码和UI DLL同步提交；包含于`publish`总耗时，不可相加作总开销。只在原15秒汇总时输出，不逐帧刷日志。自测重点是频繁切换时的发布峰值和鼠标飞控回中、F6开关后的列表及事务回执；尚未宣称实机性能收益或冲突已解决。

核心 `dualsp_execute_memory_v1` 直接接收操作、身份、配置、请求号等参数并返回本次结果；目录走 `dualsp_catalogue_memory_v1`。状态通过 `dualsp_publish_memory_v1` 交换不可变快照，动作由 `dualsp_drain_actions_memory_v1` 领取一次。连续同来源、尚未领取的直选只保留最后目标，其他动作截断合并；原生轮切和齐射不合并。游戏线程最终仍检查许可、身份、在途状态和请求号。

旧 `native-command.txt`、`native-status.json`、`ui-actions.json`、`ui-state*.json`、`catalogue*.json/txt` 不再参与运行。遗留文件不被消费，也不自动删除，旧取证脚本不能用它们代表当前状态。

文件访问限于配置初始化/实际变化保存及备份、首次资源/字体/音频加载、按需读日志与有界后台日志。未变化配置按上次成功保存快照跳过，失败不更新快照。布局 JSON 在 DLL 内存常量中解析；运行不读研究证据文件。纯网格成功加载后按资源生命周期保有，只加载当前组合需要的条目。已校验提示音 PCM 按路径跨任务复用，换 WAV 后需重启。此边界不等于引擎/系统完全没有磁盘访问，依据见[文件访问审阅](../../evidence/mount-animation-file-io-20261021.json)。

日志后台限速批量写入，mod 四份、native 六份，每份最多 1,000,000 字节；队列有界，忙时丢弃、抑制重复，调用线程不等待磁盘，最后记录可能未落盘。管理页日志默认收起，展开/刷新才读最近 64KiB。性能计量与内存读取批次约束见[工程经验](engineering-lessons.md)。

alpha2之后的未构建源码为非CFA的`switch`请求增加`SP_SWITCH_COST`：复用原九段边界，只计已到达阶段的时长，结束计时后投递一条日志；不启用逐次内存查询或炮口详细计时。CFA仍用`CFA_SWITCH_COST`修订4，保留详细统计；两类计量开销和修订不同，不跨类直接对比。两者均是核心同步事务范围，不能当作完整帧时间，也不能与包含它们的Lua `native_switch`相加。

会话头的`LOG_SESSION version`由统一构建入口读取根`VERSION`，通过同一`AC7MULTISP_VERSION`定义注入核心及UI；更新模块也使用该值。日志模块缺少该定义时停止编译，避免再以旧版本默认值误标；Lua的`DUALSP_LOADED`只记录加载事件，不再独立维护版本号，按同一PID关联会话头。运行时不另读版本文件。历史日志和已冻结DLL原字节不修改。

## 数量、配置与视觉隔离

原生配置编号为 `0/1/2`，逻辑选择是 MSL/SP1/SP2/SP3，SWP 模型池与 Socket 是另一层映射。配弹先计原生部件，再按整数百分比向上取整。方案、会话、检查点各持有比例；保存设置不补充当前库存。

有符号负库存表示原生无限，保留原负值并显示 `---`；零为空弹。调试“无限弹药”“快速装填”默认关闭，仅本次会话生效，只作用于受管 SP。无限保持当前库存、不补满；快装将合格普通消耗型 SP 等待缩短至最多一秒，排除持续效果及 PLSL/HGP/MGP。ADMM 等有限弹池仅在精确资格下唤醒窗口内 `-1` 停用槽，保留 `-2` 原生等待、池长度、库存和原生生成流程；切换开关先按旧规则结算，检查点不追溯应用新开关。

兵装操作与外观接管分别成功或失败。外观资格失败仅停该视觉绑定并归还网格、显隐和动画请求，不把已完成兵装事务改报失败。活对象归还失败保留账本继续收尾，已销毁/序列号变化对象不再解引用。完整布局容量、实际库存与当前显隐分别设计，规则见[数量与映射](multi-sp-mount-design.md#数量与映射)。

任务模型与机库模型是两个平级设置，默认均开启。任务项覆盖飞行、补给和过渡，机库项只管准备/STANDBY/PART；模型快捷键只改任务项。按场景给核心许可，禁止用两项 OR 代替真实任务状态。关闭机库模型归还租约并跳过预加载，再开启由有效页面重建。

## 身份、缓存与预览

任务只取实际受控玩家，机库只取 `HangarManager.LoadedPlayerPlane`。地址、UObject 索引、序列号共同构成弱身份；资源、反射字段、父链和归属另行核对。新实例重新采集原生归还基线，纯资源缓存不能延长玩家/世界生命周期。

alpha2之后的未构建源码将`ContinuousReadBatch`的对象表头及24字节条目分别整块读取，`alive/identity`仍逐次核对地址、序列号和PendingKill/Unreachable位；`entry`保留仅检查弱身份的原语义，供临时Root清理使用。批次只合并当前纯读取的页验证和表头，不缓存跨帧对象事实。通用模型显示在单个组件内合并身份及显隐位读取，逻辑取位在映射前合并玩家/管理器身份；每次可能重入的引擎调用之前结束批次。

反射动态字段名由活跃闭包持有固定字符串数组，避免加载器保存字节视图后 Lua 字符串回收。此规避不改通用加载器、不缓存 UObject；旧悬空键须完整重启清除。依据见[F-22 准备页记录](../../evidence/f22-preparation-string-lifetime.json)，不推定其他退出故障同因。

绑定核对完整类/包、网格、池、Socket 双射及碰撞资格。通过引擎 `SetStaticMesh` 换网格并记原值，不写网格指针或碰撞配置。借位和动态挂点让可见模型与真实离架共用实际 Socket，活动机构读取当帧世界变换；骨更新未完成时旁路本次映射，不强行求值。静态碰撞保持资格见[挂载设计](multi-sp-mount-design.md#资源资格与运行归还)。

场景/皮肤/预览实例正常换代时先归还旧上下文，再等待新入口，不作为永久结构错误。稳定预览约 100ms 巡检、失败归还约 200ms 重试；加载等待不能用超时冒充资格通过。CFA 任务外由 Lua 和核心双重原生旁路，不建立多挂预览、骨隐藏或替换；任务内和补给沿专用策略。

## 第三方机体与特殊兵装

目录按 PPDT 基础引用、SDT 涂装引用与真实类父链核对，不按 `_sNN/_typeNN` 后缀猜身份。坏行按机体隔离，同编号冲突拒绝；实际兵装取当前预览/玩家实例的三个 SpecialWeaponConfig。展示资料不足可降级为类代号/OTHER/空性能条，不因此授予写入许可。基础同槽类吻合才沿用作者 PWDT。

现行名称共用修复将PPDT `Reference`严格绑定为实际`SoftClassProperty`、40字节软类引用；旧代码要求`SoftObjectProperty`而使真实引用导出失败。两类共享软引用数据布局不代表反射类型名相同。恢复真实类路径后，基础同槽兵装类一致时保留作者展示代号；更换皮肤导致实际类不一致时仍走现有回退，不按编号把自定义兵装改成原版，也不放宽加载状态、对象身份或写入资格。该字段绑定适用于所有目录行，不硬编码F17V/ADF-11别名。原修复范围和研究阶段边界见[同类问题回执](../../evidence/mod-aircraft-reference-and-ircm-audit-20261024.json)。

换涂装、对象或兵装类会使旧草稿签名失效，排队和写入前再次核对。已配置飞行/补给持有受控快照；第三方脚本运行期热换类会报告 `EXTERNAL_SP_CHANGE`，不能把新库存记入旧逻辑槽，也不构成完整外部蓝图兼容协议。

电子战、UAV及IRCM依真实CDO父类、回调、装填/结束归属契约准入，不单看WeaponID或名称。S-44/Gleipnir的HPM即使复用编号31仍按实际WeaponUAV处理；真实ElectronicSupportMeasures走电子战。非Raven不套Raven固定三武器限制，真Raven的回收模型/TLS附着守卫保留。持续引用仍保留弱身份、发射代次、原生分配与回收、64项上限和收尾隔离。

IRCM使用`ContinuousKind::Interceptor`，仅接受`/Script/Nimbus.LaserInterceptor`派生、发射即装填且无延后装填归属、已核对的原生Tick/初始化/结束/Release/Retire回调，以及未挂接的独立根组件。源于S32只读激活和自然退场现场：10秒有效期、2秒尾迹，最终12.0008秒非活动；原生搜索/拦截/结束代码完整范围、所属玩家检查与最终回收首次按9855922指纹核对。保留Actor原生Tick、目标搜索、作者蓝图事件和寿命，不以ECM分支代替IRCM。

IRCM旧实例纳入现有双引用数组保有、临时Root和发射代次账本；额外记录独立根组件的弱身份，重建后检查其没有被换成或挂上新的挂架。Release/Retire只隔离旧代对当前SP的装填通知，Actor自身的结束、尾迹和回池继续执行；补给、检查点及失败收尾沿现有完整End/Retire路径。Lua资格返回增加第六项`interceptor`，新增`dualsp_mod_interceptor_supported`能力门禁，核心与Lua须成套接收；真实拦截器改用其他编号时也不能绕过准入失败。RectennaBarrier仍不支持，未知回调或附着结构拒绝。F-14IA的副油箱IRCM及机库依赖崩溃不因同名资源而自动放行；现有提前退让保持。名称及IRCM修订已随正式2.26.0进入main；原研究回执保留当时未编译的事实，总体验收不扩大为全部皮肤和组合逐项通过。

F-14IA 整族与三 SP 资料不完整机体提前原生退让；目录资格不等于任意 Mod 可用。依据见[第三方静态资料](../../evidence/mod-aircraft-compat-static.json)及[特殊兵装契约](../../evidence/mod-special-sp-contract-20261022.json)，逐类研究从[研究索引](../research/README.md)进入。

### 通用兼容适配流程

本节是兼容流程的唯一设计正文。基线为main `19b1528`、正式2.26.0；来源985cfdc及b95afa2经alpha3集成并获作者总体正常反馈，已正式接收为2.26.1；完整构建与交付结果以[项目状态](../../README.md)及对应回执为准，不将正常验收扩大为异常路径逐项通过。评估来源为`codex/docs-mod-compatibility-review`的`921b8df`；逐机原包、分组及用户反馈仍在[兼容性续研](../research/mod-aircraft-compatibility.md)维护。

基础多SP、持续效果、多挂外观、舱门收尾、附加输入是独立能力。第一版将持续效果和舱门接入共用故障账本，不把所有历史适配一次重写，也不新增逐机控制器、外部插件加载器或任意脚本回调。目录展示及Lua机体退让保持原边界，CFA专用发射与Raven回收机制仍保留原生约束。

共用流程为：**识别真实资源 → 核对能力契约 → 捕获本次身份及责任 → 执行原生事务 → 完成引用/临时保有归还 → 检查故障后发布结果**。显示名、机体编号、配置表命中均不能独立授予写入资格；能力降级不得扩大另一能力的权限。

| 层 | 第一版职责 | 扩展约束 |
|---|---|---|
| 描述表 | `continuous_sp_profiles.hpp`登记三类原生回调/装填契约及三项TLS资源例外；正式2.26.1的`aircraft_bay_profiles.hpp`含八项资源与三种舱门策略，未发布F35候选扩为九项/四种 | 满足已有契约的新机体直接复用；仅资源不同优先改对应描述表，不向主事务增加机名分支 |
| 能力模块 | `continuous_sp.hpp`负责效果引用和原生通知；`aircraft_bay_animation.hpp`负责限定舱门输出 | 类型/资源仍逐次或按原绑定边界核对；未知生命周期拒绝，不靠新增表项冒充机制已安全 |
| 故障账本 | `CompatibilityFailures`只保存弱身份、首个原因、阶段及重复次数，不读取引擎或执行清理 | 每种能力独立实例；调用方提供归属证据，不能按菜单简称共用故障状态 |
| 主事务 | 用统一的`continuousRequireRuntime`检查当前上下文，提交前再次检查 | 不认识新增机型；视觉失败仍原生退让，不撤销已完成的配弹事务 |

**故障范围：**持续效果的通知、UAV结束、Drain和异常收尾失败时，再次核对玩家、激活器和Level弱身份及归属；全部吻合才登记为该玩家实例故障。该实例的多SP缓存读写、资格查询及HUD就绪读取停止，不能只禁用一个按钮后继续使用不可靠库存。同一玩家换配置或重新开关总功能不解除故障；其他玩家实例可按原契约重新准入，但不能借用仍有故障的同一个激活器。无法确认上述归属时，或临时Root释放失败时，保持进程级多SP拦截，要求重启游戏。本版不实现自动重试、定时解锁或不明状态恢复。

舱门使用独立账本：失败清除绑定与事务快照，保留原生Parts调用；只停止对应玩家实例的舱门能力，不影响持续效果、库存与其他机体。绑定身份尚未取得就失败时只拒绝本次绑定，不错误隔离上一机体。总门禁清绑定不会清故障；同一实例不反复尝试。资源精确资格和算法仍以[挂载设计](multi-sp-mount-design.md#多机舱门收尾源码候选待逐机验证)为准。

舱门策略按输出性质复用：`Shared01Close`补齐旧聚合域收尾，`PublicSwitchContinuity`仅保留同事务公共进度，`SelectedIndependent`只控制某个原生配置对应的`swc1/2/3`独立输出。单路策略参数为配置索引及“模型开时关闭”，执行时再核当前armed/配置和实际模型开关，不接收机型回调；开舱只沿原生公共进度，收拢沿原生速率，模型开启时的关舱覆盖仅写独立输出。CFA-44为本次首个配置，Light旧单路写入者已撤出；资源与用户规则的唯一正文见[挂载设计CFA专节](multi-sp-mount-design.md#cfa切换与ecm当前策略)。作者已确认alpha3两侧模型开关下CFA机腹舱正常，正式2.26.1保留该实现。

未发布的F35候选新增`IndependentClose`及有限同舱配置集合参数，将旧F35三独立/三聚合输出与同舱快照移入共用模块。外观开关、外观归还和外观故障不再撤销F35舱门能力；唯一写入者、资源范围、恢复时序变化和待验证项见[官方内舱续研](multi-sp-mount-design.md#官方内舱与活动机构续研2026-10-28未发布)。这不是所有机体自动取得舱门或布局资格。

同分支普通Su-57新混挂候选复用局部机构模块，以`local_pool`指定唯一活动供位架，原四机缺省值2不变；只有实际呈现的架取得更新租约。共用舱门配置增加“仅有效模型绑定需要连续性”，普通Su-57仅在新多SP模型开启时保0/1共舱进度，模型关闭仍沿既有行为；Light公共舱快照排除该机。七组合、任务内显示门禁和未验证边界仅在上方挂载正文维护，候选尚未编译或实机通过。

**记录与清理分开：**每个能力最多保留64条玩家故障；同一玩家保留首次原因并累计重复次数，诊断文本有界且按UTF-8边界截断。只有对象表地址/序列号证明旧玩家身份已消失，才可回收局部故障记录；持续效果还要求旧激活器身份也已消失，避免新玩家借用旧组件绕过保护。PendingKill、换机、失去控制或账本清空均不算清理完成。容量耗尽时关闭该能力的后续接入，不覆盖旧记录。故障记录回收不删除效果账本、原生引用或未归还Root，进程级故障不随门禁切换清除。

临时Root另有64项责任表，仅登记本模块实际设置的Root位。正常重建在恢复两组原生引用后显式释放Root，析构仍兜底；释放失败保留责任项和进程级故障。构造失败、Drain收尾和原生回调期间的错误均须在后续初始化或成功回执前检查，不能仅记录日志后报告成功。责任表为空同样不是解除进程级故障的充分条件，本版不提供强制解锁入口。

**成本边界：**三类原生持续兵装共用一次最多64层父链分类，装填、回调、IRCM附着及代码指纹检查保留，不缓存动态实例结论；TLS仍限原三项资源。健康故障门禁直接返回，不新增对象表/父链/数组读取。局部故障存在时才在原接口调用中核对作用域和回收记录，无新增线程、全局Actor扫描、逐帧日志或文件访问。原候选数组去重和引用扫描未改，性能收益尚未测量。

后续确需新增机制时，在能力模块实现独立的预检、写入区、提交和归还边界，说明所持引用、原生结束职责、失败影响范围及继续条件；特殊资源只通过描述表选择已审阅的机制。禁止通过特殊适配直接改主程序许可、其他机体的输入/弹药、全局动画或共享作者资源。不能证明安全归还时保留原生或限制具体能力，不为追求完全兼容扩大接管。

后续验证范围包括：原三类持续兵装及TLS契约不回退；局部通知/Drain/Raven清理异常后的换机与新任务；相同地址新序列号、同激活器复用、Root释放失败、故障容量上限；舱门失败后原生Parts恰调用一次、跨机型独立、门禁重开不重试；事务期间出现故障不得返回成功。此清单仅描述后续完成条件，不表示已编写或执行测试。

兼容重构本身不修改Lua导出参数/返回值、管理协议或配置schema；新错误来自同一双语文字源。产品正式版本为2.26.1；旧2.26.0及alpha候选、来源和回执原样保留。此次验收只依据作者实际反馈，不据源码重构追认异常路径验证。

## 选装与调试换机

准备/补给使用原生控件和购买记录。选装显示列表过滤未购买项，原三项配置编号保持；左下说明取游戏本地化的真实兵装长说明，保原生页脚与换行。页面/兵装代码缓存随文本文化变化清空。入场淡入、分帧构建和提前遮挡仍属研究，现有加载等待不保证覆盖原生入场的每一帧。

原生页面的固定英文标签与双语描述/提示按[文字资源边界](../user/interface/README.md#原生选装与补给的语言边界)维护；指定标签调用现有翻译接口时明确传入英文，不改变共用译表、页面结构或选装事务。

调试换机列表支持名称/代号/编号搜索、官方/Mod 与首字母筛选，只绘制可见行，选择本身不换机。完整三 SP 目录机体可尝试；所有带 DLCID 的候选（含 Mod 与替换条目）都须由 IsDLCOwned 确认拥有，未拥有、查询失败或官方许可元数据未知时不准入。非 DLC 基础机体保留原购买提示，不写购买记录；调试许可不传给补给。调试方案临时持有，不保存为个人方案。

Mod候选通过资格检查后，优先读取游戏`AircraftShort_Name_<code>`显示名；接口未就绪、缺键或返回无效文字时沿用目录名称/代号，不影响资格。只缓存成功解析的字符串，游戏实例或文本语言变化时失效，不跨刷新持有原生对象。CFA-50使用内部代号`fa50`、编号241，正式名称参与搜索和首字母筛选，代号及编号仍可搜索；快速任务共用该候选列表。此源码修订尚未编译或实机验证。

换机通过原生 RestartLevel 重开整关并重置进度。暂停时 F6 可借用已有原生暂停，普通关闭不解除；明确应用换机时核对原世界/Pauser/UIManager，先归还本Mod暂停，经 CloseMenuAndResumePlay 确认所有暂停解除后再重开。仍有其他暂停则拒绝并回滚，不清原因位、不伪造旧菜单。新世界实际 Pawn、类父链、控制器和兵装均吻合才确认成功，不自动重复重开。

开场按真实机体及所选三个原生配置编号查询方案；剩余外挂机体的逐组合原生退让见[挂载设计](multi-sp-mount-design.md#剩余外挂机体候选未发布待验证)。未适配通知呈现后约三秒消失，不等待呈现或延后兵装；有方案时保留“加载多SP模型”与既有分帧等待，至少显示一秒的条件不拖延兵装就绪。只在开场/组合变化查询，不增加持续扫描。

快速任务和任务内换机共用`debug_aircraft.contentOwned`：`Base`、空标记及`Patch`属于非付费内容，`Patch`不向`IsDLCOwned`申请许可；其他明确DLC标记继续要求查询成功且已拥有。候选仍要求完整三SP目录并遵守原生退让，提交请求时重新核对。修复前两处把`Patch`误当付费DLC，造成大量Mod候选消失；本机A组177行中118行使用该标记，数量不代表所有机体已通过实机验收。

## 机炮齐射

原生 MGP/PLSL 加上明确登记的23个自定义炮类组成25项精确名单；Lua 候选与核心执行同时核对默认对象名、WeaponID 与实际按住连发字段。编号0有效，不能被真假判断丢弃；HGP 文案不代表任意同名/同编号替换类均支持。完整名单及静态边界见[批量记录](../../evidence/gun-salvo-mod-pod-survey.json)，Adler/XR302 的来源和观察见[研究索引](../research/README.md)。

核心分别记住真实 GUN/SP 输入，将自有 SP 按住与真实 SP 合并。Lua 仅临时选择方案中的唯一合格 SP；内部重建不当作真实松键，下一调度确认仍按住后恢复 GUN 并追加 SP。松开立即归还额外输入，再在原身份内限时恢复原选择；真实 SP 未释放时最多等一秒。人工选择优先并取消旧恢复权。

暂停、失焦、补给、检查点、关闭或身份失效均清本功能责任，旧按住不重放。射速、整组炮口、扣弹和冷却仍由原生处理；切槽仍可能有间隙。同方案多个合格 SP 拒绝联动，当前单原生 SP 池不支持不同 SP 真正并发。

## 保持注视与镜头保持

当前交互取代早期 L3 注视、R3 长按回中和角度自动回正方案：

- 手柄与键盘锁定注视独立，默认均关闭；启用后 Y 满0.2秒或实际游戏键盘注视键切换持续注视，正常起止静默，无目标/错误仍提示。
- L3 松开回正，R3 短按松开换视角、满0.3秒切换镜头保持。双摇杆组合只留原生干扰弹，取消单键候选并锁到两侧松开；不改 XInput 返回值或模拟干扰弹。
- 普通环视保持支持手柄及键鼠，默认关闭；右杆以相对角速度积分，25ms 平滑响应，正常长帧用完整 delta，超过100ms清速度、不追赶停顿。竖轴反转与俯仰限位保留；2.26.2 alpha1按[连续环绕设计](../research/camera-orbit-smoothing.md)接入水平多圈、速度交接和普通座舱输出作用域，实际平滑程度与渲染连续性待实机验证。
- 持续注视同一弱身份目标时，普通视角切换一次性交接原生注视缓存/进度；后续追踪仍原生。特殊/委托镜头不复用普通姿态。
- NEXT 有 normal/vr 排序模式，默认 normal；vr 仅在原生 NEXT 同步作用域按实际相机方向临时排序候选，结束归还，不写当前目标或发射。候选资格和历史避让仍原生，不启用 VR 设备；与 AC7MouseAim 的 F2 HMD 可能冲突。
- 白点独立、默认关闭，机头和实际相机三维夹角严格超过5°才显示。Lua 约20ms发布原子显隐/心跳，渲染端不读游戏对象；超过150ms、隐藏HUD或特殊镜头时隐藏。

功能均受单人、前台、普通视角、当前玩家与心跳许可约束；暂停/管理/失焦/断连/离场清姿态及手势，恢复重新播种，不重放。角度自动回正已移除，旧设置不作为当前功能说明。交互研究见[研究索引](../research/README.md)，输入和生命周期经验见[工程经验](engineering-lessons.md)。

正式2.26.1把镜头保持和目标注视的玩家/组件链校验分别合成短`ContinuousReadBatch`。镜头调度先核对原绑定的七个实例、视角组件类弱身份、父链/实际链接及输入列表地址/数量/容量；全部未变才复用绑定时已核实的类型资格。任何失配立即走原来的就绪等待及完整重绑，不设置跨帧身份有效标记。特殊视角判据、前台/心跳、按键边沿、鼠标轴、XInput返回值、姿态积分、原生调用及手势交接顺序沿原路径；此次只减少读取准备成本；alpha3获作者“其他功能均正常”反馈，未单独补造全部输入组合的逐项记录。

## 任务HUD与中央武器简称

Lua 游戏线程约20ms调度，正式飞行 HUD 通常约100ms同步，成功切换/重建立即提交最终状态；同步周期不是画面刷新率。右下原生面板扩展为 MSL 与最多三组 SP，保 GUN/MSL/SP/FLR/DMG 顺序。中央独立 TextBlock 使用简称，原生瞬时提示隔离以免重叠。

名称/数量、样式与箭头按变化写入；控件重建/树查找主要在绑定、槽数或字号改变时。两处共享核心一次就绪采样，直接核数组、库存、计时和待完成模型标记；未锁目标不等于未就绪。装填剪影由原生刷新并继续推进。

2.26.2 alpha1接收HUD来源a3f591a，将两处名称亮度规则集中到`weapon_names.lua`：简称精确为PLSL、MGP、HGP的名称始终使用各自原有正常亮度，包含短暂装填与空弹；其余武器未就绪时仍保留正常亮度的35%。此规则只影响文字及其阴影，不修改核心就绪结果、弹药、装填剪影、发射或齐射资格；不按WeaponID扩大到其他自定义炮类。中央常驻/切后1秒的显隐计时不变。“始终正常亮度”不表示强制常驻或在隐藏HUD时显示。绿色线框十字键已按作者要求撤回，当前源码不包含该图标功能。此候选仅完成静态审阅，未编译、测试或实机验证。

`central_weapon_display` 支持 `always` 与 `switch_1s`，当前默认后者。短显只由真实最终选择变化启动，重复/拒绝选择、MSL 预载与预热不延时；首次绑定只建基线。用游戏时间，暂停不消耗，重绑/回退/模式变化清旧计时。约100ms周期检查截止，卡顿时可更晚，不能保证逐渲染帧精确一秒。HUD 失败独立归还原控件，不撤销成功兵装事务。

## VR模式的5°生效范围（未发布）

本候选从正式2.26.1/main `800f858`建立，来源5cd8df0及`src/view_target.hpp`已纳入2.26.2 alpha1集成分支。用户选择的NEXT模式保持保存值，临时参考方向不回写设置，也不发模式切换通知。

| 已选模式 | 实际相机前向与机头前向夹角 | 本次NEXT计算 |
|---|---|---|
| 普通 | 任意 | 原生普通逻辑 |
| VR | ≤5°（含边界） | 原生普通逻辑 |
| VR | >5° | 原有视角中心优先排序 |

`viewTargetOutsideCenter`共用RootComponent四元数与实际相机缓存前向的点积判断，5°余弦仅模块初始化时计算一次，不求反三角函数。白点使用同一函数和阈值；白点配置关闭、HUD隐藏或渲染信号未更新均不影响选目标条件，不拿UI显隐当运行许可。

每次原生NEXT入口在既有玩家弱身份、归属、游戏线程、前台/心跳和普通视角核对后，读取本次实际相机缓存，立即判断是否越过5°。居中直接调用原函数一次，不进入候选遍历/排序、原序归还对象或参考视点替换作用域；偏离时才执行已有VR分支。作用域外仍为原生参考，兵装自身的原生参考分支不被强制改写。没有额外调用NEXT、直接切换当前选中目标或清除近期历史；方向变化在下一次原生NEXT计算时生效，不承诺UI提示逐渲染帧同步。

新增开销为一次固定大小四元数读取及少量数学运算/分支，不随候选数量增长；居中跳过现有VR候选处理。钩子仍只在原有启用入口安装一次，跨越阈值不反复装卸钩子、不分配新线程、不保存配置、不增磁盘访问或逐帧日志；错误仍沿既有本功能停止及原生兜底路径。边界附近来回摆动可能改变NEXT排序，但不引入额外重算或缓冲分配。这是静态成本判断，未测量帧率或耗时，不作为性能保证。

本轮只人工静态审阅、差异格式及保护文件核对；依用户指令始终不编译/安装，也不写/运行测试、不操作游戏。尚待后续明确授权核对5°边界、往返跨界、白点关闭/HUD隐藏、各普通视角、暂停/失焦/换机后的归还，以及实际NEXT与手感。未改正式版本、配置或接口协议，不将旧正式验收追认为新行为验证。

## 管理界面与配置

管理协议22、配置19、注视4、镜头8、换机2、视角选目标3，核心/UI/Lua须成套。协议22在管理状态及完整保存动作中新增`startup_update_check_enabled`布尔值，避免混用旧界面时静默漏存；更新上下文v1入口兼容原单参数，并接受第二个0/1整数传递已加载的启动检查选项。管理四页为基础功能、视角、调试、版本和更新，日志位于调试页；草稿与保存状态分离，关闭放弃未保存修改。顶栏版本与更新模块使用同一版本宏。正文独立滚动，页脚左侧保留保存/关闭顺序，右侧固定保留免费及禁止倒卖声明和作者入口；窄窗口将水印移到按钮下方贴右并按内容换行。作者入口不受 Mod 总开关禁用。中文/英文统一维护，作者名字不翻译。

当前新配置：任务/机库模型、十字键直选、齐射开启；两种注视、镜头保持和白点关闭，中央简称切后1秒，NEXT normal。F6 管理，齐射 Ctrl+Alt+F5、镜头保持 Ctrl+Alt+F6；轮切组合与任务模型快捷键默认未绑定。有效配置19保留；不兼容旧配置先完整原字节备份再生成新默认，不用历史迁移候选替代当前策略。

完整组合优先于同主键单键，快捷键共同避让回中；文本输入、捕获、连发及前台门槛保留。十字键请求标明来源，渲染端和游戏线程双重核对开关，关闭后仍维护按键基线，避免重开补发。alpha1的退格预读/原始消息隔离未消除用户在暂停菜单中的误操作，且空格仍触发原生确认。alpha2把退格与空格成套接管：WH_KEYBOARD/WH_GETMESSAGE预读只阻断，实际取出后按键及来源分别记账；空格的字符和重复只由首个接管来源投递一次，字符消息不重复插入，改键不顺带输入字符。原始消息按Win32约定清理；关闭后继续消费所接管按压的尾沿，失焦清账。

单独的消息隔离不能代替按键状态隔离：静态导入确认游戏还使用GetAsyncKeyState/GetKeyState/GetKeyboardState。新增`panel_keyboard_state.hpp`仅过滤这些函数由游戏主EXE发起的退格/空格读取；面板自身、ImGui、其他DLL和其他应用仍读原始结果。范围受前台窗口、运行许可和面板输入所有权约束；关面板后等物理松开及消息尾沿均归还再结束过滤，不伪造输入、不写系统键表、不强行重设原生暂停。钩子部分失败只撤回本轮已创建项并记录诊断，不移除别的模块已有钩子。未增加扫描或文件读取，界面关闭且无尾沿时快速旁路；已纳入[alpha2完整构建](../../evidence/2.25.3-alpha2-exe-delivery.json)，尚未测量性能或实机验证，也未动态证实本次具体漏过的调用栈。

Win32依据：[键盘状态与消息时序](https://learn.microsoft.com/en-us/windows/win32/learnwin32/keyboard-input)、[Raw Input独立读取](https://learn.microsoft.com/en-us/windows/win32/inputdev/raw-input)。本轮反馈和静态边界见[记录](../../evidence/2.25.3-alpha1-feedback-alpha2-source.json)。

普通短通知一秒，重要/警告/错误三秒；统一上方居中、`ACMultiSP: ` 前缀，同帧顺排，中英文一致。管理使用原生暂停，仅归还自己取得的暂停，没有系统静音机制。

## 版本和更新

更新模块独立位于 UI DLL。F6更新栏提供“启动游戏时检查更新”，默认开启，与其他管理草稿一起点击保存后持久化，关闭界面不提交。有效配置19缺少此字段时仅在内存补true，保留全部旧设置与方案，实际保存时沿用原字节备份；已有false不被默认值覆盖，非法类型仍报错，不增加配置版本而触发重置。

Lua仅在菜单模式或保存后的启动选项变化时发布上下文与选项，首次主菜单消费本次启动的自动检查机会：选项关闭则不创建联网线程；本次游戏中重新开启不会补发自动请求，下次启动生效。自动检查的两秒后台延迟结束后再次核对选项，已关闭则在联网前退出；已经开始的请求不强行中断。服务在接收已加载配置前默认不自动联网。手动检测不受此开关影响，可随时按既有运行许可重试，检查中禁用按钮。低优先级线程用受限WinHTTP读取不超过32KiB清单，校验后发布不可变快照；失败不自动循环重试，不影响武器控制。

只在任务外提示新版，进入任务即隐藏提醒。候选/正式版本分别比较；旧 `schema_version=1/preparing/package=null` 与当前 `schema=1/preparing` 仅显示“更新信息尚未发布”，不给旧包新版入口。HTTP/WinHTTP失败原因留日志。版本、检查按钮及状态紧凑排列，仅检测到新版时显示下载按钮；R2 固定标为主要下载链接并排在首位，其余依清单顺序标为备用下载链接1、2等，下载区只保留按钮。下载按钮经用户点击才交 Windows 默认浏览器，不自动下载/安装。

主要更新和作者授权正文由 [version_update_credits.hpp](../../src/version_update_credits.hpp) 引用统一生成资源，原有展开/收起及正文滚动保持。固定页脚和更新区下方反馈栏从同一中英文授权正文提取声明、作者标签/网址、邮箱和QQ群，不另写副本。反馈栏提供打开日志文件夹按钮，目标为 mod.log/native.log 实际所在的 modRoot 目录。

浏览器、作者入口和日志文件夹复用固定模块的后台系统打开线程，仅响应用户点击，不阻塞渲染线程。下载地址沿用清单域名白名单；作者入口只接收本地编入正文的编号，并在打开前限定为 HTTPS 或无附加参数的 mailto。日志目录存在性检查也在后台进行，无命令行参数、提权或包执行。清单/双入口部署规则见[Pages与R2发布更新说明](../archive/delivery/Pages与R2发布更新说明.md)。2.24.1本地包不等于线上更新流程已由用户验证。
