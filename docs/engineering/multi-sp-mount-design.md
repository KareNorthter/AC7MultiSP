# 多 SP 挂载设计

本文说明主线布局、运行显示与设计经验，并单列未发布候选。正式版本及交付状态见[项目入口](../../README.md)，不能按旧研究编号判断版本先后；运行模块关系见[架构](architecture.md)。

当前核心生成表含28架、196个非空组合；另有 F-15E、F-35C、Su-30SM 三架专项布局，以及六架机外保留、Su-47/Su-57 TGM 两架原生外观旁路。这里是策略与源码覆盖，不是39架七组合、全部场景均获实机验收。原47架有武装官方机体中的其余八架保留待办；无武装 `f104av` 不在该范围。

## 审美与功能取舍

### 重点：导弹尺寸与内外挂载顺序

用户指定顺序为：

**LACM ＞ LAGM/LASM ＞ 4AGM/6AGM/8AGM ＞ 远程空空导弹（LAAM、SAAM）＞ 中距空空导弹（4AAM、6AAM、8AAM、HVAA）＞ 近距空空导弹（QAAM、SASM、HPAA、HCAA）。**

大的优先内侧，小的优先外侧。该顺序指导后续各机型、各组合；仍须核对实际模型、真实支撑与离架净空，挂点有限允许不对称，不自动批改已验收方案。

| 原则 | 设计要求 |
|---|---|
| 完整布局 | 先按支撑、净空、对称安排完整可用位置，不按当前配弹、装填/待发窗口裁容量 |
| 七组合独立 | 三种单挂、三种双挂和三挂分别设计；少一种兵装后重新利用空位 |
| 真实支撑 | 对照 Body、挂架、原生池与 Socket，不从编号或单一网格猜位置 |
| 借位 | 明确逻辑兵装、供位池、真实 Socket；同位置不可重占，模型和实际离架共用映射 |
| 成对优先 | 普通消耗弹按实际坐标配对、左右交替使用，奇数允许相差一枚 |
| 分清对象 | 弹体、固定炮体、火箭巢、逐管口、UAV、效果源分别建规则 |
| 动态契约 | 保原生发射门槛、活动机构与真实世界取位；静止外观通过不等于离架通过 |
| 性能取舍 | 隐蔽空架或轻微瑕疵不自动恢复高频骨操作，功能取舍先获用户明确接受 |

允许已具体记录、用户接受的轻微外观瑕疵；严重离架穿插、悬空、未知支撑或功能冲突不能统称“允许轻穿模”。CFA 隐藏机构不能通过强压公共开盖进度实现，否则会阻断原生发射。

### 重点：成对位置按左右交替分配

按“左一、右一、左二、右二……”安排普通消耗弹的位置使用顺序，再按库存决定可见数量。九枚五加四、十枚五加五，零库存清空；超过布局容量的弹药留作备用库存，不凭空增加模型。

此原则已用于 F-4E 的 UGB＋SASM。显示与真实投放共用顺序，不在每次扣弹后搬移剩余模型强补对称；真实投放/装填空位允许暂时不对称，奇数多出的一枚可随投放轮转。其他已验收机体须逐方案评审，不能批量改序。

## 数量与映射

| 概念 | 含义 |
|---|---|
| 库存 | 剩余弹药，独立于位置数；原生负值无限库存保留其语义 |
| 逻辑队列 | 原生各槽的装填/冷却身份，从真实 Group 读取 |
| 待发窗口 | 同时装填或待发数量，不等于锁定数、模型池或布局容量 |
| 持久模型池 | 原生组件集合；Socket 数用于集合/身份核对 |
| 物理位置 | 布局实际使用的显示和离架点，可少于逻辑槽 |
| 固定发射器 | 炮体、巢体、管口、持续效果源，不套普通弹体库存显隐 |

`SWP1/2/3` 是原生资源组，用户 SP1/SP2/SP3 是逻辑选择，原生配置编号为0/1/2；`spXX` 必须连组解释。左右固定按机体坐标负Y/正Y，不随观察镜头变化。

减位不缩库存、窗口、锁定、齐射或冷却。多个逻辑槽可轮流共用一个物理点，少位布局不保证每次齐射都有独立模型消失。F-4E 保十二个真实 UGB 位置而按库存显隐；CFA 的 ADMM 原池126个发射组件不表示126枚实体弹；RKT 的管口数不等于巢体数或逻辑队列长度。

## 资源资格与运行归还

静态分区保材质、Socket、父链、非索引字节和全部LOD，主/深度/邻接索引不得跨区裁面；名称编码与资源回读需成立。缺省 BodyInstance 不能当作 NoCollision。

普通资源和跨池弹体借位核对 NoCollision；登记的七机19份静态派生挂架及后续精确反馈资源可按碰撞保真资格保留原生 BlockAllDynamic。资格由 [mount_rack_collision.hpp](../../src/mount_rack_collision.hpp) 核对源/派生包、BodySetup弱身份、父链/尺寸/GUID及完整碰撞证明，禁止自动覆盖配置；真正换网格前后再比对组件碰撞模式、Profile、ObjectType和响应，不直接改碰撞放行。见[七机证据](../../evidence/native-seven-collision-preservation.json)。

任务与预览共用每实例恢复账本。原生显隐请求继续记账；新实例重采基线，不继承旧所有权。单挂、关闭模型、场景/机体换代或资格失败归还原网格、显隐、Tick/骨更新与动画责任；失败保留存活对象责任，失效弱身份不解引用。视觉失败不撤销已完成的兵装事务。

补给预览与任务使用同一组组件时，两个布局可以登记不同的派生挂架。重新绑定先联合核对组件弱身份、同一飞机与同一原网格弱身份，当前网格允许等于原网格或任一存活记录中的已登记替换；不能让旧任务的三SP挂架记录否决当前双SP预览的合法挂架。归还和实际换网格仍逐项执行原有严格校验；未知网格、原网格不一致或资源失效继续回退，不清掉失败保护后强制重试。Rafale M补给中由三SP切换双SP候选的现场和静态路径见[本轮修订](../../evidence/2.25.3-alpha4-preview-log-source.json)，已完成[alpha4完整构建与封装](../../evidence/2.25.3-alpha4-exe-delivery.json)，实际连续切换、取消和补给后起飞仍待用户实测。

### CFA切换与ECM当前策略

CFA 多挂隐藏 ECM 的 `SWP3` 双显隐位及 `SWPCover_01/04` 两支机构，保 Body 与 `sp31` 效果源。绑定核七骨父链、网格和骨架，原生 `HideBoneByName/PBO_None` 不改碰撞。单ECM原生，公共舱门仍可打开；不能把门关住实现隐藏。

| SP→MSL | 公共机构原生关闭，机腹独立通道按下方策略收拢 |
| SP→另一SP | 保存真实请求/阶段/进度，完整事务结束按请求号恢复一次 |
| 半开时切SP | 继续推进，不冻结或跳全开，不提前许可发射 |
| 重复当前SP | 不额外重建/开合 |

**机腹独立舱（2.26.1）：**用户确认关闭多SP模型时，ADMM除机背外还在机腹显示第三组模型，切EML/ECM会空开机腹舱、回MSL不关闭；开启多SP模型时机腹为空，也会随任意SP打开。用户最终更正要求为：**多SP模型开启时机腹始终关闭，关闭时仅当前使用ADMM才打开**，不采用此前“开启时始终打开”的误述。

**EML稳定取位优化（2.26.1，作者验收有效）：** 原生普通显示也会查询发射位置；炮口维护现分为资格发现和轻量核对，不能再按“只有开火时进入”设计成本。重建提交强制发现；正常取位先核对快照，变化则在本次调用内重新发现，不靠延迟轮询补救。快照只记录本机挂架子组件的弱身份、类、父组件、Socket、潜在目标的Template字段/资源身份及是否进入炮口账本，最多256项；不延长对象生命周期，不记录实时世界变换或取代原生显隐账本。

稳定路径仍逐项读取实际子组件地址，核对数组地址/长度/容量、对象索引/序列号、类身份、父链和Socket；潜在左炮口还核对Template字段布局、当前引用和资源身份。因此同长度数组替换、地址复用、挂点变化及空/非目标Template转成目标均会立即触发重新发现。类型继承链、名称解码、反射字段查询和容器扩容留在发现路径；没有跳过子组件变化检查，也没有跨帧复用可读内存区域。

稳定核对共用一个局部`MountIdentityBatch`，只收集仍可见的已知目标，批次内不调用引擎。真正隐藏前重新核对目标并结束读取批次，再调用原生显隐；引擎调用前使资格快照失效，后续取位重新发现。原生隐藏回调只跨调用保存账本值的副本，避免重入时引用已被移除的map节点。最新原生可见请求继续留在独立账本，关闭模型、补给重配、换机和失败归还只丢资格快照，活对象归还失败仍保留账本重试。轻量取位的组件/父链/Socket校验也合成短读取批次，在`GetSocketTransform`之前结束；位置、原生选槽、弹药、装填和输入处理沿既有路径。研究采样和人工验收范围见[性能评估](../research/runtime-performance.md#cfa-eml持续掉帧研究)。

同批追加的未构建源码还合并轻量挂架的管理器/激活器/模型池身份核对，以及CFA骨架资源、枚举和字段布局检查。布局循环可接收同一纯读取调用者的批次；保留租约条件、池元素核验和所有骨隐藏/恢复操作。函数参数getter不沿用字段读取批次，原生骨查询、显隐、动画Tick及取位前后的必要身份校验继续执行。不把“复用批次”变成跳过重建后维护，也不跨原生调用保存可读区间。

发射批次边界还要求活动批次、收尾、按住输入和未消费队列为空才受控切换。队列修补不能代替重建前原生解除旧锁定；该正确性结论及历史证据从[研究索引](../research/README.md)进入。

**仍需区分本体和挂架：**XFA三型挂架全消费公共`spwc`，其轨道数A为6/11/1、B为11/11/6、C为11/17/1；TGM两架各10根公共轨道。新候选不复活非当前挂架的原生Tick/NoSkeletonUpdate，不调整显隐或复制姿态，因此本体收尾通过不等于所有挂架机构通过。CFA序列100帧，其余101帧，始终由各自原生节点求值。若只剩挂架冻结，继续采集该组件的请求、当帧骨发布和原生停用现场，不用关闭公共值或伪造发射全开来掩盖。

### 官方内舱与活动机构续研（2026-10-28，未发布）

#### 共性原因与F35C源码候选

原生Parts将公共`spwc`写入当前配置对应的独立/聚合输出，并不自动收拢每条旧配置输出。模组允许跨配置重建兵装后，旧值可能继续驱动本体或挂架。这个问题与多SP外观布局资格不同：关闭外观只归还组件显示，不会替原生完成旧通道收尾。CFA-50顶部、普通Su-57、DarkStar已有同类收尾；CFA-44机腹也使用独立输出策略。公共`spwc`重复展开则是另一个问题，不能用强制关舱统一掩盖。

F35C在2.26.1中还有明确的接线缺口：`bindF35Cover`受`fixedMountEnabled/fixedMountFailed`限制，外观归还同时清空`f35Cover`，同舱重建快照也处在外观门禁内。因此关闭模型后，原本修复旧通道冻结的逻辑一起退出。此为静态可确认的缺口；尚未取得本次用户现场，不能排除其他叠加原因。

本轮将F35C唯一写入者迁入[共用舱门模块](../../src/aircraft_bay_animation.hpp)，删除旧F35状态、Parts分支和外观事务快照，使用[有限资源表](../../src/aircraft_bay_profiles.hpp)的`IndependentClose`策略：

- 核对原版`f35c` Pawn、本体网格/AnimClass及配置0/1/2的SOD/4AAM/8AGM完整兵装包；分域旗帜沿用已采样的6。单SP、模型关闭及外观局部失败均可独立绑定；总功能关闭仍停止接管。未知替换资源退回原生，不批量放行同编号Mod机体。
- 保留原三独立输出收尾及三聚合输出公式：当前通道取原生结果，非当前按原生`delta / 0.4 × speed`收至`-0.01`；原生完整Parts每次恰执行一次。没有增加骨显隐、强制求值、Tick接管、全局扫描或每帧反射。
- SOD↔4AAM限定为配置集合`0b011`。真实SP互切中保存请求、阶段和七路实际进度，完整重建及`keepArmed`后按同事务、同代身份恢复一次；切换后的第一帧仍沿用旧方案的0/1最大开度继承。全开时保持全开，半开时继续，不能从零再展开。8AGM边界、MSL往返、补给/检查点不套同舱快照。
- 新旧兵装有活动保舱或主动关闭请求时不覆盖其请求；快照先消费再写，事务退出清理。失败只停该实例舱门能力，不再连带关闭全部多SP外观；外观开关不会清除舱门故障记录。重新出击后重核。

相较旧F35实现，本次新增共用模块的玩家/世界/资源弱身份检查，并把同舱快照恢复点从Init后移到完整`keepArmed`后。因此必须重新观察实际效果及性能，不能称等价迁移已获实机通过。现有公共域机型的算法不因F35加入而改变；XFA-33B/TGM此前“恢复后仍重复展开”的反馈继续有效。

统一修复采用“共用算法＋逐资源准入”，不向所有机体写同一组偏移：`Shared01Close`处理0/1聚合域，`SelectedIndependent`处理单路独立输出，`IndependentClose`处理经核实的三独立/聚合域，公共域仅处理事务连续性。只有确认本体和挂架实际消费域后才新增资源项；F22/TGM等纯公共域不套非当前独立通道收尾。来源、原生分派及F35对照见[域研究](../../evidence/sp-bay-domains.json)、[原生代码研究](../../evidence/sp-common-bay-control.json)和[七机资源比较](../../evidence/bay-domain-multi-aircraft-static-20261024.json)。
