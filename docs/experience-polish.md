## 机库与补给流程

出击为“机体 → SP1 → SP2 → STANDBY”。在 STANDBY 选择 SELECT SP WEAPON 可重新走两步。SP2 返回到 SP1；SP1 返回取消草稿并执行原生返回。决定/返回仍读取游戏映射，松开本次按键后自动交接，不要求再次按键；按住期间保持当前页面。交接的短暂期间不打开 F8，以免切断提交事务。

原生机库没有已核对的反射式决定/返回接口。新增 `dualsp_preparation_action` 只对当前兵装页交付一次菜单输入边沿，实际跳转、决定音和存档校验交给原生 Tick。SP1 编号先映射到原生可选行；同一原生帧内记录跳转回执，避免下一帧页面已关闭而漏判。收到回执且保存的 SP1 一致后，才保存双 SP 配置。接口不操作 SORTIE，不启动任务。异常、拒绝或超时必须报错，不自动重试或猜测成功。

补给继续保留 SP1 → SP2 → YES/NO，默认 NO；YES 经已有原生起飞入口执行，成功事件才应用和保存。原生起飞前的控件树恢复与阶段身份校验沿用 0.1.8，避免扩大已经实玩通过的收尾改动。SP1 阶段同样不展示历史 SP2。

STANDBY 使用已保存方案和当时的比例；F8 修改的全局比例只进入下一份新草稿。左侧飞机性能与部件保留，GUN/MSL/FLR 保留。右栏布局来自 1920 逻辑坐标的现场控件，沿用游戏整体缩放；不同分辨率、长文本与手柄仍待实测。

## HUD 与选择音

用户补充：旧 HUD 并非只闪一帧，而是持续到中央 START MISSION 提示结束。本轮日志显示任务世界在 `01:45:04Z` 被发现，HUD 在 `01:45:37Z` 才接管，间隔 33 秒。原调用依赖 `ready()`，把显示初始化推迟到了允许武器操作之后。候选将显示与武器初始化分开，长开场不计入“任务 HUD 缺失”的五秒诊断。

中央常驻简称沿用原生正常 Alpha 0.5，再乘就绪系数 1 或 0.5；不增加淡出计时。关闭右下显示仍会采样中央所需状态。采样失败明确报告并恢复原显示，不能用旧就绪值继续假装正常。中央常驻开关关闭后，仍恢复游戏的原生短暂提示。候选 1 的中央透明度已由用户实测正常，候选 2 不改此实现。

候选 1 的 VR Sound 对象与 MSL/SP1 共用一份媒体，但采用不同的空间化设置；独立对象不代表独立音源，旧研究结论已修正。候选 2 按用户选择复用 `HUD_WEAPON_RESTRICT_RELEASE`，媒体编号 875504770，约 0.34 秒，**不是新增自制音频**。试听位于 `Temp/experience-audio/SP2-proposed.wav`，实际游戏听感仍待复测。通过原生激活器的音效包装器播放，继续使用游戏的声音管理；不创建独立系统播放器、不复制游戏音库进发行包。

`dualsp_selection_audio` 在重建前绑定玩家，只过滤两个精确选择事件名；逻辑选择完成才播放一次。初始化、补给、检查点同步不播放选择提示，相同目标不重播，拒绝选择不播新提示。世界变化或控制器报错时解除过滤。底层仍执行完整飞机切换与锁定槽音效收尾，不改 seeker 参数。
